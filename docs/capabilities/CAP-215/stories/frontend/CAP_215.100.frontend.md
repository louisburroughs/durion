## 1. Story Header

### Title
[FRONTEND] [STORY] Inventory Availability: View On-hand and ATP by Location / Storage Location

### Primary Persona
Service Advisor

**Persona Metadata**
- `primary_persona`: `Service Advisor`
- `canonical_persona`: `Service Advisor`
- `persona_family`: `Service Advisor`

### Business Value
Enable accurate quoting and scheduling by showing backend-authoritative on-hand, allocated, and available-to-promise (ATP) quantities for a part at a selected business location (optionally narrowed to a storage/bin location), in the product base UOM.

---

## 2. Story Intent

### As a / I want / So that
- **As a** Service Advisor  
- **I want** to query and view on-hand, allocated, and ATP for a part by location and optionally by storage location  
- **So that** I can quote and schedule customer work realistically based on current stock availability

### In-scope
- A frontend screen/workflow to request availability for a single `productSku` at:
  - a parent **location** (`locationId`, aggregated across storage locations), and/or
  - a specific **storage location** (`storageLocationId`, bin-level scope)
- Display returned quantities (read-only): `onHandQuantity`, `allocatedQuantity`, `availableToPromiseQuantity`, `unitOfMeasure`
- Treat “no inventory history” as a valid success response with 0 quantities and a clear empty-state message (DECISION-INVENTORY-004)
- Support deep-linking via canonical query params and auto-run once per load when required params are present (DECISION-INVENTORY-014)
- Moqui screen(s), transitions, and service-call wiring to **Moqui proxy** availability endpoint (no direct Vue → inventory backend) (DECISION-INVENTORY-002)
- Deterministic error handling and correlation ID display in error technical details (DECISION-INVENTORY-003, DECISION-INVENTORY-012)
- Sensitive data handling: do not log availability quantities client-side (DECISION-INVENTORY-011)

### Out-of-scope
- Editing inventory, allocations, receipts, or ledger events (read-only screen)
- Expected receipts in ATP calculation (ATP v1 excludes expected receipts; UI displays what backend returns and does not compute) (DECISION-INVENTORY-004)
- UOM conversions (request/response in product base UOM only; UI does not convert) (DECISION-INVENTORY-004)
- Batch/multi-SKU availability queries (single SKU per request only)
- Auto-refresh polling/loops (explicitly not implemented; user-initiated refresh only) (DECISION-INVENTORY-004)

## 4. Preconditions & Dependencies

  - `GET /inventory/availability` (DECISION-INVENTORY-002, DECISION-INVENTORY-004)

  - Query params: `productSku` (required), `locationId` (required), `storageLocationId` (optional) (DECISION-INVENTORY-004, DECISION-INVENTORY-014)

  - `GET /inventory/locations` for `LocationRef` picker (DECISION-INVENTORY-007, DECISION-INVENTORY-008)

- Correlation ID convention:
  - UI includes `X-Correlation-Id` header on requests and reads it from responses when present (DECISION-INVENTORY-012)

## 7. Business Rules (Translated to UI Behavior)

### Validation
- `productSku`:
  - Required; trim whitespace; reject empty/whitespace-only before calling backend (STORY_VALIDATION_CHECKLIST)
- `locationId`:
  - Required; must be selected via picker (no free-text UUID entry) (DECISION-INVENTORY-001)
- `storageLocationId`:
  - Optional; if provided, must belong to selected `locationId`
  - UI enforces by filtering picker by `locationId`; if backend still rejects, show field-level error (DECISION-INVENTORY-001, DECISION-INVENTORY-003)

### Enable/disable rules
- Disable “Check Availability” until `productSku` and `locationId` are present and valid
- Disable storage location picker until `locationId` is selected
- Disable submit while request is in-flight (double-submit protection)

### Visibility rules
- Results panel hidden until a query succeeds (including success-with-zeros)
- Error banner/panel shown only on failed query
- Technical details section in error panel is collapsed by default and may show:
  - correlation ID (if present)
  - HTTP status
  - deterministic error code/message when safe (DECISION-INVENTORY-003, DECISION-INVENTORY-012)

### Error messaging expectations (deterministic mapping)
- 400 / 422 (validation):
  - Prefer field-level messages when error schema provides `fieldErrors`
  - Otherwise show: “Invalid request. Check the inputs and try again.”
- 401:
  - Follow app convention: redirect to login/session refresh (DECISION-INVENTORY-012)
- 403:
  - “You do not have permission to view availability.”
  - Do not display any quantities (DECISION-INVENTORY-012)
- 404 (SKU not found):
  - “Part/SKU not found. Verify the SKU and try again.”
- 404 (location/storage not found):
  - “Location or storage location not found.”
- Timeout / network:
  - “Availability service is unavailable. Try again.”
  - Provide Retry button (DECISION-INVENTORY-004)
- 5xx:
  - “Availability service is unavailable. Try again.”
- Sensitive data rule:
  - Do not log numeric quantities to console/telemetry; only log timing/status and correlation ID (DECISION-INVENTORY-011)

**Decision rationale (applied):**
- Endpoint path/envelope resolved to Moqui proxy `GET /inventory/availability` with plain JSON (DECISION-INVENTORY-002, DECISION-INVENTORY-003, DECISION-INVENTORY-004).
- Pickers required; free-text UUID entry disallowed in v1 user flows (DECISION-INVENTORY-001).
- Deep-link param names and auto-run-once behavior are canonical (DECISION-INVENTORY-014).
- Quantities are sensitive; client logs must omit them (DECISION-INVENTORY-011).

## 12. Acceptance Criteria

### Scenario 1: Location-level availability success
**Given** I am an authenticated Service Advisor  
**And** I am on the Inventory Availability screen  
**When** I enter `productSku = "SKU-123"` and select `locationId = "LOC-A"`  
**And** I submit “Check Availability”  
**Then** the UI calls `GET /inventory/availability` with `productSku="SKU-123"` and `locationId="LOC-A"` and no `storageLocationId`  
**And** the UI displays `onHandQuantity`, `allocatedQuantity`, `availableToPromiseQuantity`, and `unitOfMeasure` from the plain JSON response  
**And** the UI does not compute or modify these values client-side.

### Scenario 2: Storage-location scoped availability success
**Given** I have selected `locationId = "LOC-WAREHOUSE"`  
**And** the storage location picker is filtered to `LOC-WAREHOUSE`  
**When** I select `storageLocationId = "BIN-1"` and submit  
**Then** the UI calls `GET /inventory/availability` including `storageLocationId="BIN-1"`  
**And** the UI displays quantities scoped to that storage location.

### Scenario 3: Deep-link auto-run once per load
**Given** I navigate directly to the Availability screen URL with query params `productSku="SKU-123"` and `locationId="LOC-A"`  
**When** the screen loads  
**Then** the UI auto-runs the availability query exactly once  
**And** it does not re-run automatically due to reactive state updates  
**And** subsequent changes to inputs do not auto-run until I click “Check Availability”.

### Scenario 4: No inventory history returns zeros (success state)
**Given** the backend returns a success response with `onHandQuantity=0`, `allocatedQuantity=0`, `availableToPromiseQuantity=0`  
**When** I submit a valid query  
**Then** the UI shows a success results panel with all three quantities displayed as 0 in the returned `unitOfMeasure`  
**And** the UI indicates “No inventory history” without treating it as an error.

### Scenario 5: Product not found (404)
**Given** I submit `productSku="SKU-DOES-NOT-EXIST"` with a valid `locationId`  
**And** the backend responds `404 Not Found` for the SKU  
**Then** the UI shows “Part/SKU not found. Verify the SKU and try again.”  
**And** the inputs remain editable for correction  
**And** no results panel is shown.

### Scenario 6: Location or storage location not found (404)
**Given** I submit a query with a `locationId` or `storageLocationId` that does not exist  
**And** the backend responds `404 Not Found`  
**Then** the UI shows “Location or storage location not found.”  
**And** inputs remain editable for correction.

### Scenario 7: Forbidden (403)
**Given** I submit a valid query  
**And** the backend responds `403 Forbidden`  
**Then** the UI shows “You do not have permission to view availability.”  
**And** the UI does not display quantities  
**And** the UI does not log any returned quantities.

### Scenario 8: Required field validation prevents submit
**Given** I am on the Inventory Availability screen  
**When** I leave `productSku` empty (or whitespace) and click “Check Availability”  
**Then** the UI shows an inline validation error on the SKU field  
**And** no backend call is made.

### Scenario 9: Timeout shows retry without auto-retry
**Given** I submit a valid query  
**And** the request does not complete within 8 seconds  
**Then** the UI shows a timeout message and a “Retry” action  
**And** the UI does not automatically retry the request.
