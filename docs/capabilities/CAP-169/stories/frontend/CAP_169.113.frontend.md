### Title

### Business Value
When an original part is unavailable, the advisor can quickly choose an authorized substitute with correct customer pricing and audit traceability, reducing delays and avoiding manual pricing math.

## 2. Story Intent

### As a / I want / So that
- **As a** Service Advisor  
- **I want** to fetch authorized substitute candidates for a part line and see availability + pricing (including policy/capability flags)  
- **So that** I can select a substitute confidently and keep the estimate/work order accurate and auditable without manual math.

### In-Scope
- UI action on a specific **part line item** to “Find substitutes”
- Support **both Work Orders and Estimates** (single picker UX; backend enforces eligibility)  
- Display of substitute candidates with:
  - availability status (and optional reason/message)
  - price quote (or “Price unavailable”)
  - substitution/policy flags as provided by backend (no inference)
- Apply selected substitute to the target line item via backend call
- Enforce “cannot apply without price unless manual price permission” at UI level using backend-provided `canEnterManualPrice` and candidate pricing fields
- User cancel flow leaving the line unchanged
- Empty states and error states aligned to backend outcomes
- Idempotent apply behavior (send `Idempotency-Key`)

### Out-of-Scope
- Authoring/editing substitution policies or SubstituteLink master data (inventory/product domain SoR; workexec consumes)
- Inventory receiving/picking flows
- Notification delivery for any alerts
- Manual price entry UX (this story only gates apply; it does not implement manual price capture)
- Reprice workflow after a substitute is applied (separate story)

## 6. Functional Behavior

### Triggers
- User clicks `Find Substitutes` on a specific part line item for:
  - a Work Order (`targetType=WORK_ORDER`), or
  - an Estimate (`targetType=ESTIMATE`)

### UI actions
- Open picker dialog
- Immediately show loading state
- Fetch candidates using `targetType`, `targetId`, `lineId`
- Render candidate list rows with:

  - availability status + optional message
  - price display (formatted currency) or “Price Unavailable”
  - policy flags badges (as returned)
- Selection:
  - single-select candidate
- Confirm:
  - calls apply endpoint with selected candidate id and optional pricing override fields if required by contract (none in v1 UI)
- Cancel:
  - closes without calling apply endpoint
- Optional: toggle “Show unavailable”:
  - refetch candidates with `includeUnavailable=true`

### State changes (frontend)
- Dialog state machine:
  - `idle` → `loading` → `loaded` | `error`
- Selection state:
  - `selectedCandidateId`
- Apply state:
  - `applying` (disable controls; show spinner)
- After apply success:
  - emit `applied` event and close dialog
  - refresh parent line items (see Service interactions)

### Service interactions
- Fetch candidates:
  - 1 call on dialog open
  - additional call when toggling `includeUnavailable`
- Apply substitution:
  - 1 call on confirm, with `Idempotency-Key` header
- Refresh:
  - preferred: use apply response to update the single line in UI
  - fallback: re-fetch the document (work order/estimate) or the part lines list

## 7. Business Rules (Translated to UI Behavior)

### Validation
- Required inputs before opening picker:
  - `targetType` in `{WORK_ORDER, ESTIMATE}`
  - `targetId` (opaque string)
  - `lineId` (opaque string)
- Apply button enabled only when:
  - a candidate is selected AND
  - candidate is eligible AND
  - (`price` is present) OR (`price` is missing AND `canEnterManualPrice=true`)
- UI must not infer eligibility from local availability alone; it must rely on backend-provided eligibility fields and backend enforcement.

### Enable/disable rules
- `Find Substitutes` action:
  - enabled by default when the line exists and the document is editable
  - if backend provides `canSubstitute=false` (either on line or via candidates response), disable and show reason
- Candidate row:
  - if `availabilityStatus=UNAVAILABLE` (when included), render disabled and non-selectable
  - if `eligible=false`, render disabled and show reason (if provided)
- Apply/Confirm:
  - disabled when selected candidate is disabled/non-eligible
  - disabled when price missing and `canEnterManualPrice=false`

### Visibility rules
- Policy flags are displayed only if provided by backend (no inference).
- “Show unavailable” toggle is visible only if backend supports `includeUnavailable` parameter (assumed supported per DECISION-INVENTORY-007).

### Error messaging expectations (standard envelope parsing)
- `DUPLICATE` (409): “This substitution was already applied. Refresh to see the latest line.”
- `CONFLICT` / stale version (409): “This line changed since you opened substitutes. Refresh and try again.”
- `NOT_ELIGIBLE` (400): “This part line is not eligible for substitution.”
- `FORBIDDEN` (403): “You don’t have permission to substitute parts on this document.”
- `NOT_FOUND` (404): “The document or line item could not be found. Refresh and try again.”
- `SERVER_ERROR` (5xx): “We couldn’t load substitutes right now. Try again.”

(Decision rationale: DECISION-INVENTORY-011 standardizes error parsing; UI messages are ergonomic and do not change policy.)

## 9. Service Contracts (Frontend Perspective)

> This story is frontend-focused; it defines the required frontend-facing contract shape and error handling. Exact Moqui service names may differ; implementers must map these to Moqui REST endpoints or screen transitions consistent with the repo.

### Load/view calls

**GET Substitution Candidates**
- Purpose: return policy-filtered substitutes with availability + pricing (if available), plus flags and capability gating.
- Request:
  - `GET /rest/api/v1/workexec/substitution-candidates?targetType={WORK_ORDER|ESTIMATE}&targetId={id}&lineId={id}&includeUnavailable={true|false}`
- Response (JSON):
  - `targetType`, `targetId`, `lineId`
  - `canEnterManualPrice` (boolean)
  - `candidates[]` (as defined in Data Requirements)
  - optional `asOf`
- Error handling:
  - 400/403/404/409/5xx return standard error envelope (DECISION-INVENTORY-011)

(Decision rationale: DECISION-INVENTORY-007 defines a stable picker contract supporting both targets and eligibility enforcement; DECISION-INVENTORY-011 defines error envelope.)

### Create/update calls

**POST Apply Substitute**
- Purpose: apply selected substitute to the line item; create immutable substitution history; return updated line or require refresh.
- Request:
  - `POST /rest/api/v1/workexec/substitutions:apply`
  - Headers:
    - `Idempotency-Key: <uuid>` (DECISION-INVENTORY-012)
  - Body:
    - `{ targetType, targetId, lineId, candidateId }`
- Response (JSON; one of):
  - Option A (preferred): `{ updatedLine: {...}, substitutionHistoryId: "..." }`
  - Option B: `{ success: true }` (UI must refresh document/lines)
- Error handling:
  - 409 includes standard envelope with `code` and `correlationId`; UI treats as non-applied and prompts refresh

### Submit/transition calls
- None beyond apply substitution.

### Error handling expectations
- UI parses standard envelope:
  - `code` drives message mapping
  - `correlationId` is displayed in an expandable “Details” area for support (optional) and logged client-side

## 11. Alternate / Error Flows

### Validation failures (client-side)
- Missing `targetId`/`lineId`:
  - do not open dialog
  - show inline error “Missing line identifier; refresh and try again.”

### Concurrency conflicts
- Apply returns 409:
  - keep dialog open and show error banner with “Refresh candidates” action
  - “Refresh candidates” re-calls candidates endpoint (same `includeUnavailable` setting)
  - parent screen is refreshed only after a successful apply or explicit user refresh

### Unauthorized access
- Candidates fetch returns 403:
  - show permission error state in dialog; no list rendered
- Apply returns 403:
  - show permission error; do not change UI line

### Empty states
- No candidates returned:
  - show “No authorized substitutes found.”
- Candidates returned but none eligible/available:
  - show “No substitutes are currently available.”
- If `includeUnavailable=true`:
  - show unavailable candidates disabled with reason

### Partial failures
- If pricing is unavailable for some candidates:
  - show those candidates with “Price Unavailable”
  - apply gated by `canEnterManualPrice` as described

## 12. Acceptance Criteria

### Scenario 1: View priced substitute candidates and apply (Work Order)
**Given** I am a Service Advisor viewing `WorkOrderEdit` for a work order with a part line `lineId`  
**When** I click “Find Substitutes” for that part line  
**Then** the system calls `GET /rest/api/v1/workexec/substitution-candidates` with `targetType=WORK_ORDER`, `targetId`, and `lineId`  
**And** I see a list of candidates with availability, pricing (when available), and policy flags (when provided)  
**When** I select a candidate where `eligible=true` and `priceStatus=AVAILABLE` and confirm  
**Then** the system calls `POST /rest/api/v1/workexec/substitutions:apply` with an `Idempotency-Key` header  
**And** the part line updates to show the substitute part number/description and price (either from response or after refresh)  
**And** no manual pricing math is required in the UI

### Scenario 2: View priced substitute candidates and apply (Estimate)
**Given** I am a Service Advisor viewing `EstimateEdit` for an estimate with a part line `lineId`  
**When** I click “Find Substitutes” for that part line  
**Then** the system calls the candidates endpoint with `targetType=ESTIMATE`  
**And** I can apply an eligible priced candidate using the same apply endpoint  
**And** the estimate part line updates accordingly

### Scenario 3: No authorized substitutes
**Given** the candidates endpoint returns `candidates=[]` for the selected line  
**When** the picker renders  
**Then** I see “No authorized substitutes found.”  
**And** the Apply action is disabled  
**And** no line item changes occur

### Scenario 4: Include unavailable candidates (optional toggle)
**Given** the picker is open  
**When** I enable “Show unavailable”  
**Then** the system refetches candidates with `includeUnavailable=true`  
**And** candidates with `availabilityStatus=UNAVAILABLE` are shown disabled with an availability reason/message (when provided)  
**And** I cannot select/apply an unavailable candidate

### Scenario 5: Pricing unavailable and manual price not permitted
**Given** a candidate is returned with `eligible=true`, `availabilityStatus=AVAILABLE`, `priceStatus=UNAVAILABLE`, and `unitPrice=null`  
**And** the response has `canEnterManualPrice=false`  
**When** I select that candidate  
**Then** I see “Price Unavailable”  
**And** the Apply/Confirm action remains disabled  
**And** no apply request is sent

### Scenario 6: Pricing unavailable and manual price permitted (gating only)
**Given** a candidate is returned with `eligible=true`, `availabilityStatus=AVAILABLE`, `priceStatus=UNAVAILABLE`, and `unitPrice=null`  
**And** the response has `canEnterManualPrice=true`  
**When** I select that candidate and confirm  
**Then** the UI allows the apply request to be sent  
**And** if the backend rejects due to missing required manual price fields, the UI shows the backend error message and does not mark the line as applied

### Scenario 7: User cancels
**Given** the substitution picker is open  
**When** I cancel/close the dialog  
**Then** no apply request is made  
**And** the original line item remains unchanged

### Scenario 8: Concurrency conflict on apply
**Given** I opened substitutes for a line item  
**And** the line item changes on the server before I confirm  
**When** I attempt to apply a substitute  
**Then** the apply request returns `409 Conflict` with a standard error envelope including `correlationId`  
**And** the UI shows “This line changed since you opened substitutes. Refresh and try again.”  
**And** the UI does not show the line as substituted until a successful refresh confirms it

### Scenario 9: Unauthorized access
**Given** I do not have permission to substitute parts on the document  
**When** I attempt to open the picker or apply a substitute  
**Then** the backend returns `403 Forbidden`  
**And** the UI shows “You don’t have permission to substitute parts on this document.”  
**And** no line item changes occur
