[FRONTEND] [STORY] Pricing: View Immutable Pricing Snapshot Drilldown from Estimate/WO Line (Moqui UI)

### Business Value
Enable users to **inspect and explain historical line pricing** via an immutable snapshot drilldown so that later pricing rule changes do not create confusion, disputes, or audit gaps.

---

## 2. Story Intent

### As a / I want / So that
- **As a** Service Advisor  
- **I want** to open a read-only “Pricing Snapshot” drilldown from an Estimate/Work Order line  
- **So that** I can explain how the price was calculated at the time the line was created and trust that the data is immutable.

### In-scope
- Moqui frontend screens/components to **retrieve and display** a `PricingSnapshot` by `snapshotId` (`pricingSnapshotId` on the line).
- Drilldown entry points from **both** Estimate line UI and Work Order line UI anywhere a line exposes `pricingSnapshotId`. (DECISION-PRICING-013)
- Read-only presentation of snapshot fields, with **minimum required rendering**:
  - `snapshotId`, `createdAt`, `unitPrice`, `extendedPrice` as Money objects `{amount, currencyUomId}` (DECISION-PRICING-001)
- Defensive rendering of optional snapshot fields (e.g., breakdown, applied rules, policyVersion, sourceContext), without requiring them.
- Error handling UX when snapshot cannot be loaded (404, 403, 5xx/timeout).
- Permission behavior:
  - Snapshot access is **inherited from the owning document access**; sensitive fields may be redacted by backend. UI must handle redaction/omissions without error. (DECISION-PRICING-014)

### Out-of-scope
- Creating snapshots and enforcing immutability (backend responsibility).
- Editing/updating/deleting snapshots (explicitly forbidden).
- Changing Workexec line creation flows.
- Deep-linking requirements beyond modal/drawer (a route may exist for internal wiring, but UX pattern is modal/drawer).
- Accounting reporting consumption.

## 4. Preconditions & Dependencies

### Preconditions
- An Estimate line and/or Work Order line exists in Workexec UI and has a non-empty `pricingSnapshotId`.
- User is authenticated in the POS frontend.

### Dependencies
- Pricing API is reachable from Moqui frontend runtime:
  - `GET /pricing/v1/snapshots/{snapshotId}` (DECISION-PRICING-002)
- Workexec UI already exposes `pricingSnapshotId` on line payloads (Estimate and Work Order contexts).
- Authorization is enforced by backend via inherited document access; UI must handle 403. (DECISION-PRICING-014)

### Decision rationale (applied resolutions)
- **Snapshot payload minimum** is defined by Pricing domain decisions to keep UI deterministic and avoid recomputation: render `snapshotId`, `createdAt`, `unitPrice`, `extendedPrice` using canonical Money shape. (DECISION-PRICING-001, DECISION-PRICING-013)
- **Where to show drilldown** is explicitly “anywhere a line exposes `pricingSnapshotId`”, covering both Estimate and Work Order. (DECISION-PRICING-013)
- **Presentation pattern** is modal/drawer to preserve editing context. (DECISION-PRICING-013)
- **Authorization model** is inherited from owning document access; sensitive fields may be redacted. (DECISION-PRICING-014)

### Entry points
- From **Estimate detail** screen: each line item row renders an action “View pricing snapshot” when `pricingSnapshotId` is present.
- From **Work Order detail** screen: each line item row renders an action “View pricing snapshot” when `pricingSnapshotId` is present.

### Screens to create/modify
1. **New Screen (modal/drawer content):** Pricing Snapshot View screen/component
   - Moqui screen location must follow repo conventions; implement under the Pricing UI area (DECISION-PRICING-015 guidance).
   - The screen must accept `snapshotId` as a parameter and load snapshot via a screen action/service call.
2. **Modify Screen(s):**
   - Estimate detail screen (Workexec) to add the action and open the modal/drawer.
   - Work Order detail screen (Workexec) to add the action and open the modal/drawer.

### Navigation context
- Snapshot drilldown opens in a **modal/drawer** (not a full navigation away) and closing returns to the originating document without losing unsaved edits. (DECISION-PRICING-013)
- If the implementation requires a route for the modal content, it must still be presented as modal/drawer in the UX.

### User workflows (happy + alternate)
**Happy path**
1. User views an estimate or work order.
2. User clicks “View pricing snapshot” on a line with `pricingSnapshotId`.
3. Modal/drawer opens and loads snapshot.

- 5xx/timeout/network: show “Pricing snapshot service is unavailable right now. Please try again.” with Retry.

- `GET /pricing/v1/snapshots/{snapshotId}` (DECISION-PRICING-002)

## 7. Business Rules (Translated to UI Behavior)

### Validation
- `pricingSnapshotId` must be present and non-empty before enabling the action.
- `snapshotId` is treated as an opaque identifier (no parsing/validation beyond non-empty).

### Enable/disable rules
- “View pricing snapshot” action is enabled only when `pricingSnapshotId` exists.
- If `pricingSnapshotId` is missing, action is hidden or disabled (implementation choice), but must not call the API.

### Visibility rules
- Do not attempt to pre-compute authorization; rely on backend enforcement.
- If backend returns 403, show forbidden state and ensure no snapshot data is displayed. (DECISION-PRICING-014)

### Error messaging expectations
- 404 → “Pricing snapshot not found.”
- 403 → “You don’t have access to view this pricing snapshot.”
- 5xx/timeout/network → “Pricing snapshot service is unavailable right now. Please try again.”
- 401 → follow existing app re-auth behavior.

### Sensitive-field handling (redaction)
- UI must not assume presence of sensitive fields (e.g., cost).
- If cost/margin fields are absent or explicitly redacted, show “Not available” and do not treat as an error. (DECISION-PRICING-014)

### `sourceContext` rendering
- `sourceContext` is **not shown by default**.
- If present, it is behind an “Advanced” toggle and rendered as escaped/preformatted JSON (no HTML injection). (DECISION-PRICING-014)

## 8. Data Requirements

### Entities involved (frontend perspective)
- **Workexec Document Line** (EstimateLine / WorkOrderLine or equivalent)
  - `pricingSnapshotId` (string/UUID; required to enable drilldown)
- **PricingSnapshot** (Pricing API response)
  - Required minimum fields for UI:
    - `snapshotId` (string/UUID)
    - `createdAt` (ISO timestamp)
    - `unitPrice` (Money)
    - `extendedPrice` (Money)
  - Optional fields (render if present; do not require):
    - `quantity` (number/decimal)
    - `productId` / SKU / name (if provided)
    - `breakdown` (object/array)
    - `appliedRules` / `appliedOverrides` / `appliedPromotions` (arrays)
    - `policyVersion` (string)
    - `sourceContext` (object)

### Fields (type, required, defaults)
- Money (DECISION-PRICING-001):
  - `unitPrice`: `{ amount: "<decimal-string>", currencyUomId: "<uomId>" }` (required)
  - `extendedPrice`: `{ amount: "<decimal-string>", currencyUomId: "<uomId>" }` (required)
- `createdAt`: string timestamp (required; if missing, display “Unknown”)
- `snapshotId`: string/UUID (required; if missing, treat as invalid reference)

### Read-only vs editable by state/role
- All snapshot fields are strictly read-only for all roles.

### Derived/calculated fields
- UI must **not** compute extended price from unit * quantity; display only backend-provided values. (DECISION-PRICING-001)

## 9. Service Contracts (Frontend Perspective)

### Load/view calls
**Operation:** Retrieve snapshot  
**HTTP:** `GET /pricing/v1/snapshots/{snapshotId}` (DECISION-PRICING-002)

**Inputs**
- `snapshotId` (path param)

**Success (200)**
- Must include at minimum (DECISION-PRICING-001):
  - `snapshotId`
  - `createdAt`
  - `unitPrice` as Money
  - `extendedPrice` as Money
- May include additional optional fields; UI must ignore unknown fields.

**Errors**
- 401: trigger existing authentication flow (no partial render).
- 403: show forbidden state; do not display any snapshot details. (DECISION-PRICING-014)
- 404: show not-found state.
- 408/5xx/network: show unavailable state with Retry.

### Create/update calls
- None.

### Submit/transition calls
- None.

### Error handling expectations
- Do not display raw error payloads to users.
- Log only safe identifiers:
  - `snapshotId`
  - originating document identifiers (estimateId/workOrderId/lineId) if available
  - HTTP status and backend `errorCode` if present
- Do not log sensitive snapshot fields (e.g., cost) even if present. (DECISION-PRICING-014)

## 10. State Model & Transitions

### Allowed states
- `idle` (modal closed / no snapshot selected)
- `loading`
- `loaded`
- `error:notFound`
- `error:forbidden`
- `error:unavailable`
- `error:invalidReference` (missing/empty snapshotId)

### Role-based transitions
- Authorization is enforced by backend; 403 transitions to `error:forbidden`.

### UI behavior per state
- `idle`: no snapshot UI visible.
- `loading`: show loading indicator; disable retry until response.
- `loaded`: render snapshot sections; Advanced toggle available only if `sourceContext` present.
- `error:invalidReference`: show “Invalid pricing snapshot reference.” with Close.
- `error:notFound`: show not-found message with Close.
- `error:forbidden`: show forbidden message with Close.
- `error:unavailable`: show unavailable message with Retry + Close.

## 11. Alternate / Error Flows

### Validation failures
- Missing/empty `pricingSnapshotId`:
  - Action hidden/disabled.
  - If modal is invoked via direct wiring with missing id, show `error:invalidReference` and do not call API.

### Concurrency conflicts
- Not applicable (read-only). If snapshot is unexpectedly missing, treat as 404.

### Unauthorized access
- On 403:
  - Clear any previously loaded snapshot data from UI state before rendering error.
  - Do not allow “Advanced” content to remain visible.

### Empty states
- If optional arrays (e.g., `appliedRules`) are empty/missing:
  - Show neutral empty-state text: “No rule details were provided for this snapshot.”
- If optional fields are missing/redacted:
  - Show “Not provided” / “Not available” without implying policy.

## 12. Acceptance Criteria

### Scenario 1: Open snapshot drilldown from a Work Order line (happy path)
**Given** I am an authenticated Service Advisor  
**And** a Work Order line displays a non-empty `pricingSnapshotId`  
**When** I select “View pricing snapshot” for that line  
**Then** the system requests `GET /pricing/v1/snapshots/{pricingSnapshotId}`  
**And** the snapshot drilldown opens in a modal/drawer without navigating away from the Work Order  
**And** I see `snapshotId` and `createdAt`  
**And** I see `unitPrice.amount` and `unitPrice.currencyUomId` exactly as returned  
**And** I see `extendedPrice.amount` and `extendedPrice.currencyUomId` exactly as returned  
**And** the UI does not compute or display any recalculated totals

### Scenario 2: Open snapshot drilldown from an Estimate line (happy path)
**Given** I am an authenticated Service Advisor  
**And** an Estimate line displays a non-empty `pricingSnapshotId`  
**When** I select “View pricing snapshot” for that line  
**Then** the system requests `GET /pricing/v1/snapshots/{pricingSnapshotId}`  
**And** the snapshot drilldown opens in a modal/drawer without losing unsaved edits on the Estimate screen  
**And** closing the modal/drawer returns me to the Estimate screen in the same state

### Scenario 3: Drilldown action is unavailable when a line has no snapshot id
**Given** I am viewing an Estimate or Work Order with line items  
**And** a line item has an empty or null `pricingSnapshotId`  
**Then** the “View pricing snapshot” action for that line is not available (hidden or disabled)  
**And** the UI does not call `GET /pricing/v1/snapshots/...` for that line

### Scenario 4: Snapshot not found (404)
**Given** I attempt to view a pricing snapshot with snapshotId `11111111-1111-1111-1111-111111111111`  
**When** the Pricing API responds with HTTP 404  
**Then** the UI shows a “Pricing snapshot not found” error state  
**And** no snapshot details are displayed

### Scenario 5: Not authorized (403)
**Given** I attempt to view a pricing snapshot  
**When** the Pricing API responds with HTTP 403  
**Then** the UI shows “You don’t have access to view this pricing snapshot.”  
**And** the UI does not display any snapshot details (including any previously loaded snapshot)

### Scenario 6: Pricing service unavailable (timeout/5xx)
**Given** I attempt to view a pricing snapshot  
**When** the snapshot request times out or returns HTTP 5xx  
**Then** the UI shows “Pricing snapshot service is unavailable right now. Please try again.”  
**And** I can retry the request  
**And** if the retry succeeds, the snapshot details render

### Scenario 7: `sourceContext` is hidden by default and safe when shown
**Given** the snapshot payload includes a `sourceContext` object  
**When** the snapshot drilldown renders  
**Then** `sourceContext` is not visible by default  
**And** when I expand “Advanced”, `sourceContext` is rendered as escaped/preformatted JSON (no HTML rendering)
