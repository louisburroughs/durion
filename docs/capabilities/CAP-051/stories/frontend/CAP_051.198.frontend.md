## 1. Story Header

### Title
[FRONTEND] [STORY] GL: Provide Trial Balance and Drilldown to Source (Moqui Screens)

### Primary Persona
Controller (Finance)

**Persona Metadata**
- `primary_persona`: `Controller (Finance)`
- `canonical_persona`: `Controller`
- `persona_family`: `Finance / Accounting Management`
- `actor_type`: `human`

### Business Value
Enable finance to validate General Ledger integrity and support period-end close/audits by generating a Trial Balance with traceable drilldown from balances to ledger lines, journal entries, and originating source events, including CSV export for offline workflows.

---

## 2. Story Intent

### As a / I want / So that
- **As a** Controller  
- **I want** to generate a Trial Balance for a selected accounting period with optional account and dimension filters, and drill down from balances to underlying ledger/journal/source details  
- **So that** I can reconcile the ledger, investigate anomalies, and produce evidence for audit and close.

### In-scope
- Moqui **screens, forms, transitions** for:
  - Trial Balance criteria selection and on-screen results
  - Drilldown flow: Trial Balance → account ledger lines → journal entry → source event view (read-only)
  - CSV export of the displayed Trial Balance
- Permission gating:
  - Screen-level authz (Moqui artifact authz) + backend 401/403 handling
  - No UI-only security (backend remains authoritative)
- Empty/error states for no data, validation errors, access denied, and not found

### Out-of-scope
- Implementing accounting calculations/posting logic
- Defining or changing the Chart of Accounts, posting rules, or period close logic
- Creating/editing journal entries or ledger entries
- PDF export (CSV only)
- Any mutation of source events (source events are read-only references)

---

## 3. Actors & Stakeholders
- **Controller (primary):** runs Trial Balance, exports CSV, drills into sources.
- **Finance Manager/Accountant (secondary):** uses reports for reconciliation/close.
- **Auditor (stakeholder):** consumes exported CSV and drilldown evidence (read-only access).
- **System (Accounting/GL services):** provides report and drilldown data; enforces access control.

---

## 4. Preconditions & Dependencies

### Preconditions
- User is authenticated in the frontend.
- User has permission to view GL reporting (see Security/Authorization under Business Rules).
- Accounting periods exist and posted ledger/journal data exists for the selected period.

### Dependencies
Backend endpoints/services must exist for:
- Listing available accounting periods
- Generating Trial Balance with filters
- Retrieving ledger lines for an account/period/filter context
- Retrieving a journal entry by ID
- Retrieving a source event view by reference (or returning a payload summary + optional raw payload gated by permission)
- Exporting Trial Balance as CSV using the same criteria as on-screen results

**Decision rationale (resolution):** This story is buildable only if the backend provides report/drilldown read models. This aligns with Accounting domain ownership of posting artifacts and read models; UI must not compute balances client-side.

  - `/accounting/gl/source-event?sourceEventRef=...` (preferred single reference token)  
    - If backend uses structured params instead: `sourceSystem`, `sourceEntityType`, `sourceEntityId`

### Screens to create/modify (Moqui Screen definitions)
1. **`apps/accounting/screen/gl/TrialBalance.xml`**
   - Criteria form + results table + export action
2. **`apps/accounting/screen/gl/LedgerLines.xml`**
   - List ledger lines for selected account/context
3. **`apps/accounting/screen/gl/JournalEntryView.xml`**
   - Journal entry header + lines; link to source event
4. **`apps/accounting/screen/gl/SourceEventView.xml`**
   - Generic “source event details” renderer:
     - default: `payloadSummary` (curated/redacted)
     - optional: raw JSON only when permitted (see AD-009 policy)

### Navigation context
- Preserve “report context” across drilldowns:
  - `periodId` (required)
  - optional filters (account filter + dimensions)
- Provide “Back to Trial Balance” action that restores criteria and re-runs the report (server-side reload permitted; no client-side caching required).

### User workflows (happy + alternate paths)

#### Happy path
1. Open Trial Balance screen.
2. Select Period (required), optionally set account filter and dimension filters.
3. Generate report → view results with totals and balanced indicator.
4. Click an account line → view ledger lines for that account in the same period/filter context.
5. Click a ledger line → view journal entry.
6. Click source reference → view source event details (read-only).
7. Export CSV of Trial Balance using the same criteria.

#### Alternate paths
- Generate report with no results → show “No data” state; allow criteria adjustment; allow CSV export of empty result (see Business Rules).
- Drilldown to missing journal entry/source → show “Not found” with safe messaging.
- Permission denied → show access denied state; do not leak whether an ID exists.

## 7. Business Rules (Translated to UI Behavior)

### Validation
- **Period is required** before generating report.
- **Account filter**:
  - Support **RANGE** by account code (string compare is backend-defined; UI only validates non-empty and `from <= to` using lexicographic compare as a UI hint; backend remains authoritative).
  - Support **LIST** by selecting one-or-more accounts (if backend supports; otherwise hide LIST option).
- **Dimensions**:
  - Support a generic list of `{dimensionTypeId, dimensionValueId}` pairs.
  - Multiple dimensions combine as logical **AND**.
  - Each dimension type allows **one value** in this story (multi-select per dimension is out of scope unless backend explicitly supports it).

**Decision rationale (resolution):** Multi-select per dimension and dimension taxonomy are policy-heavy and not defined in the provided accounting rules; restricting to single value per dimension keeps UI deterministic without inventing policy.

### Enable/disable rules
- “Generate” disabled until `periodId` is selected.
- “Export CSV” disabled until a report has been generated successfully.
- Drilldown links:
  - Trial Balance → Ledger Lines enabled when `glAccountId` present.
  - Ledger line → Journal Entry enabled only when `journalEntryId` present.
  - Journal Entry → Source Event enabled only when `sourceEventRef` (or structured reference) present.

### Visibility rules
- Show a **balanced/imbalanced** indicator:
  - If backend provides `isBalanced`, use it.
  - Else compare `reportTotalDebits` vs `reportTotalCredits` for display only (do not “fix” or recalculate lines).
- Restricted data:
  - UI must not attempt to infer or hide “sensitive” accounts; it displays what backend returns.
  - If backend returns 403, show Access Denied and render no report data.

### Error messaging expectations
- Validation errors: inline field errors + summary.
- 401/403: “Access denied” (no record existence leakage).
- 404: “Not found” with safe messaging (no additional hints).
- 409: “Data changed; reload and retry” (used for stale report contexts if backend uses report tokens).
- 5xx/timeout: show retryable error; preserve criteria.

### Security/Authorization (explicit)
Because Accounting domain guide requires explicit permission mapping (AD-013), this story defines permissions for GL reporting:

- View Trial Balance + drilldowns: `accounting:gl:view`
- Export Trial Balance CSV: `accounting:gl:export`
- View raw source payload JSON (if supported): `accounting:events:view-payload` (reuse existing payload permission; AD-009)

**Decision rationale (resolution):** The accounting guide defines payload permission and secure-by-default principles but does not define GL report permissions. Introducing explicit, action-scoped permissions is required to ship screens without guessing role inheritance; tokens are scoped to this feature and can be mapped by security later.

## 9. Service Contracts (Frontend Perspective)

> Backend contract is required; below defines the minimum endpoints the frontend will call. Names follow the accounting `/accounting/*` namespace convention used in the accounting domain guide.

### Load/view calls
1. `GET /accounting/periods/list`
   - Request: pagination optional
   - Response: `periods[]` with `periodId`, `periodName`, `startDate`, `endDate`, `status`

2. `GET /accounting/gl/accounts/list` (for LIST filter picklist)
   - Request: optional search/pagination
   - Response: `accounts[]` with `glAccountId`, `accountCode`, `accountName`, `status`

3. `GET /accounting/gl/dimensions/list` (optional; only if backend supports dimension filtering)
   - Response: `dimensionTypes[]` each with `dimensionTypeId`, `label`, `values[] {dimensionValueId,label}`

### Create/update calls
- None.

### Submit/transition calls
1. `POST /accounting/gl/trialBalance/run`
   - Request:
     - `periodId`
     - `accountFilterType` + filter fields
     - `dimensions[]`
   - Response:
     - `generatedAt`, `currencyUomId`, `lines[]`, totals, optional `isBalanced`
     - Optional `reportRunId` (if backend supports caching/tokenization)

2. `GET /accounting/gl/ledgerLines`
   - Request:
     - `periodId`, `glAccountId`
     - optional `dimensions[]` (same as report)
   - Response:
     - `ledgerLines[]` + `currencyUomId`

3. `GET /accounting/gl/journalEntry?journalEntryId=...`
   - Response: journal entry header + lines + optional `sourceEventRef`

4. `GET /accounting/gl/sourceEvent`
   - Request:
     - either `sourceEventRef` (preferred)
     - or structured params (`sourceSystem`, `sourceEntityType`, `sourceEntityId`)
   - Response:
     - `payloadSummary` always
     - `rawPayloadJson` only when permitted (AD-009)

5. `POST /accounting/gl/trialBalance/exportCsv`
   - Request: same as `/trialBalance/run` OR `{reportRunId}`
   - Response: `text/csv` stream with safe filename

### Error handling expectations
- Error schema (canonical, reused from accounting guide):
  - `{ errorCode, message, details? }`
- 400/422: validation errors; map `details` to fields.
- 401/403: access denied; do not render partial data.
- 404: not found for journal entry/source event.
- 409: conflict/stale report token; prompt regenerate.
- 5xx/timeout: retryable error; preserve criteria.

## 10. State Model & Transitions

### Allowed states
- `Idle` (criteria not yet run)
- `Loading` (fetching report/lines)
- `Loaded` (results displayed)
- `Error` (non-field error)
- `AccessDenied`

### Role-based transitions
- Users with `accounting:gl:view` can load screens and run reports.
- Users with `accounting:gl:export` can export CSV.
- Users without permissions:
  - Entry points hidden where possible
  - Backend 403 handled as AccessDenied

### UI behavior per state
- `Idle`: criteria form visible; results hidden; export disabled.
- `Loading`: disable actions; show loading indicator.
- `Loaded`: show results + drilldown links; export enabled if permitted.
- `Error`: show error summary; allow retry.
- `AccessDenied`: show access denied; no data tables rendered.

## 11. Alternate / Error Flows

1. **No data**
   - If report returns `lines[] = []`, show “No data found for selected criteria”.
   - CSV export behavior:
     - Allow export even when empty (produces header-only CSV) if backend supports it; otherwise disable export and show backend message.

2. **Unbalanced report**
   - If `isBalanced=false` or totals mismatch, display warning banner and still render results.

3. **Broken source link**
   - If journal entry lacks source reference: show “No source reference available for this journal entry.”
   - If source lookup returns 404: show “Source event not found” and keep navigation back.

4. **Stale report token**
   - If backend uses `reportRunId` and returns 409/410: show “Report expired; regenerate” and route back with criteria preserved.

5. **Unauthorized access**
   - If any drilldown returns 403:
     - show AccessDenied
     - do not render cached sensitive data for that view
     - provide safe navigation back.

### AC2: Balanced totals indication
Given a Trial Balance is generated for period "2024-08"  
When the report totals are returned  
Then if the backend indicates the report is balanced, the UI shows a balanced indicator  
And if the backend indicates the report is not balanced (or totals mismatch), the UI shows a prominent imbalance warning while still displaying results.

### AC3: Drilldown from Trial Balance to ledger lines
Given a Trial Balance is displayed for period "2024-08"  
When I click the drilldown action for account "Revenue"  
Then I am navigated to the Ledger Lines view for that account and period  
And I see the list of posted ledger lines returned by the backend for that context.

### AC4: Drilldown from ledger line to journal entry
Given I am viewing ledger lines for an account  
And at least one ledger line has a journalEntryId  
When I select a ledger line with a journalEntryId  
Then I am navigated to the Journal Entry view  
And I see the journal entry header and all journal entry lines returned by the backend.

### AC5: Drilldown from journal entry to source event (summary)
Given I am viewing a journal entry that includes a source event reference  
When I click the source event reference  
Then I am navigated to the Source Event view  
And I see a curated payload summary returned by the backend.

### AC6: Raw payload visibility is permission-gated
Given I am authenticated without `accounting:events:view-payload`  
When I view a Source Event  
Then the UI does not display raw payload JSON  
And the UI does not request raw payload fields when the backend supports summary-only responses.

### AC7: Export Trial Balance to CSV
Given a Trial Balance report is displayed for selected criteria  
And I have `accounting:gl:export`  
When I click "Export CSV"  
Then a CSV file downloads  
And the CSV contains a header row  
And the CSV rows match the data displayed in the Trial Balance table for the same criteria.

### AC8: Access denied does not leak record existence
Given I am authenticated without `accounting:gl:view`  
When I navigate directly to a journal entry URL with a specific journalEntryId  
Then the UI shows “Access denied”  
And the UI does not indicate whether that journal entry exists.

### AC9: Missing source event handling
Given I am viewing a journal entry with a source reference  
When the source event request returns 404 Not Found  
Then the UI displays a “Source event not found” message including the reference identifier (as provided)  
And the UI allows me to navigate back to the journal entry without losing context.
