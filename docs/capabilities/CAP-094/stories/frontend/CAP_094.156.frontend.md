## 1. Story Header

### Title
[FRONTEND] [STORY] CRM Integration Admin UI: View Inbound Event Processing Logs & Suspense (Read-only)

### Primary Persona
- **Integration Support Engineer / Admin User** (human operator using the POS frontend)
- Secondary: **Data/Integration Engineer** (uses UI for debugging & validation during rollout)

**Persona Metadata**
- `primary_persona`: `Integration Support Engineer / Admin User (human operator using the POS frontend)`
- `canonical_persona`: `Integration Support Engineer`
- `persona_family`: `Technical / Platform`
- `actor_type`: `human`

### Business Value
Provide an operator-facing way to **monitor and audit inbound event processing outcomes** in CRM (success/failure/suspense) so that integration issues can be detected and diagnosed **without direct database access**, while enforcing **RBAC and redaction**.

---

## 2. Story Intent

### As a / I want / So that
- **As an Integration Support Engineer**, I want to **view inbound event processing status and inspect failed events routed to suspense**, so that **I can resolve integration issues quickly and keep CRM data current**.

### In-Scope
- Moqui/Quasar frontend screens to:
  - List and view **ProcessingLog** records (read-only).
  - List and view **SuspenseItem** records (read-only).
  - Display traceability fields: `eventId`, `eventType`, `correlationId` (exact/prefix semantics), timestamps, status, reason codes, and safe error summaries.
  - Display **payloadSummary** and **redactedPayload** only (no raw payload rendering).
- Filtering and search for operational triage:
  - by `eventType`, `eventId`, `correlationIdPrefix`, status, date range
- Role/permission-gated access with fail-closed behavior (403).

### Out-of-Scope
- Implementing the actual event consumer/handler (backend processing).
- Defining or changing event schemas for `VehicleUpdated`, `ContactPreferenceUpdated`, `PartyNoteAdded`.
- Any operator actions that mutate backend state (retry/reprocess/ack/export/mark resolved).
- Customer data CRUD driven by events (vehicle/contact/note updates themselves are backend responsibility).

## 7. Business Rules (Translated to UI Behavior)

### Validation
- Filters:
  - `eventId` must be a UUID when provided; otherwise show inline error and do not submit.
  - Date range: `to` must be >= `from`; otherwise show inline error and do not submit.
  - `correlationId` filter supports:
    - exact match, or
    - prefix match (“starts with”)
  - If user attempts “contains” semantics (e.g., UI does not provide it; but if query param is manipulated), backend returns 400 `UNSUPPORTED_FILTER` and UI shows a non-technical error banner (DECISION-INVENTORY-008).

### Enable/disable rules
- “View detail” enabled only when the row includes the required identifier:
  - Processing Logs: `processingLogId`
  - Suspense: `suspenseId`
- If backend returns 403, the screen renders access denied and does not attempt further calls.

### Visibility rules
- Payload visibility (DECISION-INVENTORY-006):
  - UI must never render raw `payload`.
  - UI may render `payloadSummary` and `redactedPayload` if present in DTO.
  - UI must render `redactedPayload` as plain text / JSON viewer without HTML interpretation.
- Sensitive fields:
  - UI must not log payload, details, VIN, license plate, or other PII to client telemetry.

### Error messaging expectations
- List load failure: “Unable to load inbound event records. Try again.”
- Detail not found: “This record no longer exists or you don’t have access.”
- Unsupported filter (400): “This filter is not supported. Adjust your search and try again.”
- Access denied (403): “Access denied. You don’t have permission to view inbound event monitoring.”

- `correlationId` (String, optional)

## 9. Service Contracts (Frontend Perspective)

> UI must call **dedicated read services** that return safe DTOs and enforce RBAC/redaction (DECISION-INVENTORY-005, -006, -007). UI must not use direct entity-find in screens for these records.

### Load/view calls

#### Processing logs list
- **Moqui REST endpoint (preferred)**: `GET /rest/api/v1/crm/integrations/processing-logs`
- **Inputs (query params)**:
  - `eventType` (optional, string)
  - `status` (optional, string)
  - `eventId` (optional, UUID)
  - `correlationId` (optional, exact match)
  - `correlationIdPrefix` (optional, prefix match; UI label “starts with”) (DECISION-INVENTORY-008)
  - `from` (optional, ISO datetime)
  - `to` (optional, ISO datetime)
  - `pageIndex` (required, int >= 0)
  - `pageSize` (required, int; backend may cap)
  - `sort` (optional; backend-defined, e.g., `receivedAt:desc`)
- **Outputs (JSON)**:
  - `items[]` (ProcessingLog DTO list fields)
  - `pageIndex`, `pageSize`, `total`

#### Processing log detail
- **Endpoint**: `GET /rest/api/v1/crm/integrations/processing-logs/{processingLogId}`
- **Outputs**: ProcessingLog DTO (detail)

#### Suspense list
- **Endpoint**: `GET /rest/api/v1/crm/integrations/suspense`
- **Inputs**:
  - `eventType` (optional)
  - `status` (optional)
  - `eventId` (optional, UUID)
  - `correlationId` (optional, exact)
  - `correlationIdPrefix` (optional, prefix)
  - `from` / `to` (optional)
  - `pageIndex`, `pageSize`, `sort`
- **Outputs**:
  - `items[]` (SuspenseItem DTO list fields)
  - `pageIndex`, `pageSize`, `total`

#### Suspense detail
- **Endpoint**: `GET /rest/api/v1/crm/integrations/suspense/{suspenseId}`
- **Outputs**: SuspenseItem DTO (detail)

### Create/update calls
- none

### Submit/transition calls
- none

### Error handling expectations
- `401`: redirect to login (project standard).
- `403`: show access denied state; do not render partial data.
- `404`: show not found state on detail screens.
- `400`:
  - For invalid filters: show inline validation if client-detected; otherwise show banner using backend `errorCode`/`message`.

- `409`: not expected for these screens (read-only), but if returned, show banner “Conflict; reload and try again.”
- `5xx`/network: show retry affordance (“Retry” button).

## 11. Alternate / Error Flows

### Validation failures
- Invalid UUID in `eventId` filter:
  - UI blocks submit and shows inline error.
- Invalid date range:
  - UI blocks submit and shows inline error.
- Unsupported correlation contains:
  - If backend returns 400 `UNSUPPORTED_FILTER`, UI shows banner and keeps prior results.

### Concurrency conflicts
- Record disappears between list and detail:
  - Detail returns 404 → show not found and provide “Back to list”.

### Unauthorized access
- User lacks permission:
  - List and detail endpoints return 403.
  - UI shows access denied; no partial data is displayed.

### Empty states
- No results:
  - Show empty state with “Clear filters” and guidance to broaden date range or remove filters.

## 12. Acceptance Criteria

### Scenario 1: View processing logs with filtering and pagination
**Given** I am logged in as a user with permission `crm.integrations.monitor.read`  
**When** I navigate to `Integration → Inbound Events` and open the “Processing Logs” tab  
**Then** I see a paginated list of processing log records including `processingLogId`, `eventId`, `eventType`, `status`, and `receivedAt`  
**And** I can filter by `status` and date range  
**And** the results update to match my filters  
**And** the response includes `pageIndex`, `pageSize`, and `total`

### Scenario 2: Correlation filter uses exact/prefix semantics only
**Given** I am on the Processing Logs tab  
**When** I filter by correlation “starts with” using `correlationIdPrefix=ESTIMATE:`  
**Then** only records whose `correlationId` begins with `ESTIMATE:` are returned  
**And** the UI does not offer a “contains” correlation search option

### Scenario 3: View processing log detail by processingLogId
**Given** I am viewing the Processing Logs list  
**When** I select a log record  
**Then** I am taken to `/integration/processing-logs/<processingLogId>` (or equivalent Moqui screen path)  
**And** I see `eventId`, `eventType`, `status`, `receivedAt`, and any provided `reasonCode` and redacted `details`  
**And** I can copy `eventId` and `correlationId` (if present)

### Scenario 4: View suspense list and detail by suspenseId
**Given** I am logged in as a user with permission `crm.integrations.monitor.read`  
**When** I open the “Suspense” tab  
**Then** I see a paginated list including `suspenseId`, `eventId`, `eventType`, `status`, `failureReason`, and `receivedAt`  
**When** I open a suspense item  
**Then** the detail loads by `suspenseId`  
**And** I see envelope metadata and failure summary  
**And** I see `payloadSummary` and `redactedPayload` only if present

### Scenario 5: Raw payload is never rendered
**Given** I am viewing a Suspense detail record that includes payload-related fields  
**When** the screen renders  
**Then** the UI does not render any field named `payload`  
**And** the UI renders `redactedPayload` as plain text/JSON without HTML interpretation  
**And** client telemetry/logging contains no payload content

### Scenario 6: Retry metadata is optional and does not break rendering
**Given** one ProcessingLog record includes `attemptCount`, `lastAttemptAt`, and `nextAttemptAt` and another does not  
**When** I view each record’s detail  
**Then** the record with retry metadata displays those fields  
**And** the record without retry metadata renders without errors and without empty placeholders

### Scenario 7: Client-side validation prevents invalid queries
**Given** I am on the inbound event list screen  
**When** I enter an invalid `eventId` value that is not a UUID and attempt to apply filters  
**Then** the UI shows an inline validation error  
**And** no backend query is executed

### Scenario 8: Unauthorized user cannot access monitoring
**Given** I am logged in as a user without permission `crm.integrations.monitor.read`  
**When** I navigate to `Integration → Inbound Events`  
**Then** I see an access denied message  
**And** no processing logs or suspense items are displayed

### Scenario 9: Detail record not found
**Given** I navigate directly to a suspense detail URL with a `suspenseId` that does not exist  
**When** the screen loads  
**Then** I see a “not found” message  
**And** a link to return to the list view
