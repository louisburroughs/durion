## Issue Body

## 1. Story Header

**Title:** [FRONTEND] Reporting: Produce Core Financial Statements (P&L, Balance Sheet) with Drilldown and Export

**Primary Persona:** Financial Controller / Accountant

**Persona Metadata**
- `primary_persona`: `Financial Controller / Accountant`
- `canonical_persona`: `Controller`
- `persona_family`: `Finance / Accounting Management`
- `actor_type`: `human`

**Business Value:** Enable finance users to reliably generate reproducible financial statements from posted ledger data, investigate balances via drilldown to source, and export reports for review/audit.

---

## 2. Story Intent

### As a / I want / So that
**As a** Financial Controller or Accountant,  
**I want** to generate a Profit & Loss and Balance Sheet for a selected period/as-of date with drilldowns to underlying accounts, journal lines, and source events,  
**So that** I can analyze financial performance/position, support period close activities, and satisfy audit/review needs.

### In-scope
- UI flows to:
  - Generate **P&L** for a date range
  - Generate **Balance Sheet** as-of an end date
  - Drilldown path: **statement line → contributing accounts → journal lines → source event reference**
  - Export generated statement output with access control enforcement
- Deterministic/reproducible report results for identical parameters (frontend must not introduce nondeterminism; rely on backend reproducibility)
- Handling empty states, validation errors, unauthorized access, and service failures

### Out-of-scope
- Defining or editing Chart of Accounts, statement definitions, posting rules, or accounting periods
- Performing postings, closing periods, or making adjustments
- Multi-entity consolidation and multi-currency presentation (unless backend explicitly supports it; not included here)
- Custom report builder / ad-hoc reporting beyond basic P&L and Balance Sheet

---

## 3. Actors & Stakeholders

- **Financial Controller / Accountant (Primary):** Runs reports, drills into balances, exports for review.
- **Auditor (Indirect):** Consumes exports and drilldown evidence; needs traceability to source events.
- **System Administrator / Security Admin:** Configures permissions for viewing and exporting reports.
- **Support/Operations:** Needs logs/trace IDs to troubleshoot report generation failures or latency.

---

## 4. Preconditions & Dependencies

### Preconditions
- User is authenticated.
- Posted ledger/journal data exists (or UI must show “no data” state).
- Backend provides endpoints/services to:
  - Retrieve statement results for given parameters
  - Retrieve drilldown levels (line→accounts→journal lines→source event)
  - Export statement output (or provide export-ready payload)

### Dependencies (blocking if absent)
- Backend reporting contract for statement + drilldown + export must exist and be stable.
- Authorization model/permissions for:
  - Viewing statements
  - Drilling down
  - Exporting
- Statement structure/mapping (how accounts map to statement lines) must be backend-defined or configured elsewhere.

**Resolution rationale applied (from Accounting domain rules):**
- **Permission gating is mandatory and deny-by-default** (Decision **AD-013**). This story therefore defines explicit permission tokens (see sections 7/10/12) and requires Moqui artifact authz.
- **Correlation/tracing standard is W3C Trace Context** (Decision **AD-008**) and must be propagated on all report/drilldown/export calls (see sections 9/13).
- **Identifier strategy is UUIDv7** (Decision **AD-006**) for any IDs returned by backend (journalEntryId, eventId, etc.); UI validates UUID format only where IDs are guaranteed UUIDs.

## 7. Business Rules (Translated to UI Behavior)

### Validation
- P&L:
  - `fromDate` required
  - `thruDate` required
  - `fromDate <= thruDate` else show inline validation error and prevent call
- Balance Sheet:
  - `asOfDate` required
- If backend returns validation errors, surface them at form level and on relevant fields when possible using `{errorCode, message, details}` mapping.

### Enable/disable rules
- **Run Report** disabled until required parameters valid.
- **Export** disabled when:
  - no report currently loaded
  - user lacks export permission
  - report is loading
- **Drilldown** disabled when:
  - report is loading
  - line indicates `drilldownAvailable=false` (or backend returns empty)

### Visibility rules
- Entry point and screen visibility:
  - Hide menu entry and block route unless user has `accounting:reports:financial-statements:view` (see Security below).
- Drilldown controls visible only when report loaded.
- For statement lines with no children, clicking shows “No underlying accounts” message and does not error.

### Error messaging expectations
- Unauthorized (401/403): show “Access denied” page or blocking banner; do not display financial data remnants.
- No data: show friendly empty state (not an error).
- Backend error: show non-technical message + trace/request id if provided.
- Do not infer accounting policy (posting rules, period close semantics) beyond backend-provided fields (Accounting domain principle: backend authoritative).

**Decision rationale applied:**
- **AD-013 Permission gating model**: deny-by-default; separate view vs export permissions; do not ship without explicit mapping.
- **AD-008 Correlation & trace standard**: propagate `traceparent`/`tracestate`; show trace identifiers for support where available.

- `JournalEntry` / `JournalLine` (draft/posted; for drilldown references)

- `FinancialStatementDefinition` (line structure and mapping; backend-owned)

### Fields (UI-facing; exact names must match backend)
#### Statement run parameters
- `reportType`: enum `{PL, BS}` (required)
- `fromDate`: date (required for PL)
- `thruDate`: date (required for PL)
- `asOfDate`: date (required for BS)
- `businessUnitId`: string/UUID (optional; only if backend supports)
- `statementDefinitionId`: string/UUID (optional; only if backend supports)
- `includeZeroLines`: boolean (optional; only if backend supports)
- `currencyUomId`: string (display-only; returned by backend)

#### Statement result
- `reportRunId` (UUIDv7) OR `resultHash` (string): stable identifier for export and drilldown context (backend-defined)
- `generatedAt` (datetime, display)
- `parameters` (echo of inputs)
- `currencyUomId` (string)
- `lines[]` each:
  - `lineKey` (string; stable identifier for drilldown)
  - `label` (string)
  - `amount` (decimal)
  - `drilldownAvailable` (boolean)

#### Drilldown: accounts
- `accounts[]` each:
  - `glAccountId` (UUIDv7)
  - `accountCode` (string)
  - `accountName` (string)
  - `amount` (decimal)

#### Drilldown: journal/ledger lines
- `entries[]` each:
  - `postedDate` (date) and/or `transactionDate` (date)
  - `journalEntryId` (UUIDv7; preferred navigation reference per AD-011 when available)
  - `ledgerEntryId` (UUIDv7; optional)
  - `description` (string)
  - `debitAmount` (decimal) and `creditAmount` (decimal) OR signed `amount` (decimal)
  - `eventId` (UUIDv7; optional)
  - `eventType` (string; optional)
  - `sourceEntityRef` (string; optional)

#### Source event reference (minimum if supported)
- `eventId` (UUIDv7)
- `eventType` (string)
- `occurredAt` (datetime; optional)
- `receivedAt` (datetime; optional)
- `sourceModule` (string; optional)
- `payloadSummary` (object/string; optional; redacted)
- `rawPayloadJson` (object/string; optional; gated by permission `accounting:events:view-payload` per AD-009)

### Read-only vs editable
- All fields are read-only except report parameters.

### Derived/calculated fields (frontend)
- Currency formatting only; no financial calculations beyond displaying backend-provided totals.
- Breadcrumb labels derived from selected items.

## 9. Service Contracts (Frontend Perspective)

> Frontend must call Accounting-owned endpoints; it must not invent schemas. Use W3C trace headers on all calls (AD-008).

### Load/view calls
1. **Run statement**
   - `GET /accounting/reports/financialStatements/run`
   - Query params:
     - `reportType` (`PL`|`BS`)
     - For `PL`: `fromDate`, `thruDate` (ISO `YYYY-MM-DD`)
     - For `BS`: `asOfDate` (ISO `YYYY-MM-DD`)
     - Optional if supported: `businessUnitId`, `statementDefinitionId`, `includeZeroLines`
   - Response (200):
     - `reportRunId` or `resultHash`
     - `generatedAt`, `currencyUomId`, `lines[]`, `parameters`
   - Error:
     - 400/422 `{errorCode, message, details}`

2. **Fetch drilldown accounts for statement line**
   - `GET /accounting/reports/financialStatements/drilldown/accounts`
   - Query params:
     - `reportRunId` OR full parameter echo (backend choice; must be consistent)
     - `lineKey`
   - Response (200): `accounts[]`

3. **Fetch journal/ledger lines for account**
   - `GET /accounting/reports/financialStatements/drilldown/entries`
   - Query params:
     - `reportRunId` OR full parameter echo
     - `glAccountId`
     - Optional pagination: `pageIndex`, `pageSize`, `orderBy` (recommended)
   - Response (200): `entries[]` + pagination metadata if paged

4. **Fetch source event summary (optional)**
   - If backend supports linking to ingestion/event read models:
     - `GET /accounting/ingestion/detailByEvent?eventId=...` (preferred if available, aligns with ingestion monitoring model AD-007)
     - or `GET /accounting/events/detail?eventId=...` (if a dedicated event summary exists)
   - Response (200): event summary including `payloadSummary`; raw payload only if permitted (AD-009)

### Create/update calls
- None (reporting is read-only)

### Submit/transition calls
5. **Export statement**
   - `POST /accounting/reports/financialStatements/export`
   - Body:
     - `reportRunId` OR `resultHash` (preferred to guarantee export matches displayed results)
     - `format` enum: `CSV` | `PDF` | `XLSX` (backend-supported subset; UI must load allowed formats from backend if provided)
   - Response:
     - Either binary stream download (recommended) OR `{downloadUrl, fileName, contentType}`
   - Authorization:
     - Requires `accounting:reports:financial-statements:export`

### Error handling expectations
- 400/422 validation: map field errors to inputs; show message.
- 401/403: access denied; clear sensitive state; do not leak existence of report runs.
- 404: show “Not found” (safe message) and offer to rerun report.
- 409: show conflict/reload guidance (e.g., “Data changed; rerun report”) only if backend uses optimistic tokens.
- 5xx/timeout: show retry option; preserve parameters; do not auto-retry.

**Decision rationale applied:**
- **AD-009 Raw payload visibility policy**: if event payload is shown at all, default to `payloadSummary`; raw JSON only with `accounting:events:view-payload`, and must not be cached or logged.
- **AD-011 Posting reference canonical identifier**: when linking to postings from drilldown, prefer `journalEntryId` as the primary reference.

## 10. State Model & Transitions

### Allowed states (UI)
- `idle` (no result yet)
- `loading` (running report or drilldown fetch)
- `loaded` (result displayed)
- `error` (error banner + retry)

### Role-based transitions
- View screen requires: `accounting:reports:financial-statements:view`
- Drilldown requires: `accounting:reports:financial-statements:drilldown` (separate from view)
- Export requires: `accounting:reports:financial-statements:export`
- Viewing raw payload (if event detail is present) requires: `accounting:events:view-payload` (AD-009 / AD-013)

### UI behavior per state
- `idle`: show parameter form, no results.
- `loading`: disable actions; show progress indicator.
- `loaded`: show results + export + drilldown affordances.
- `error`: show error summary + retry; keep parameters intact.

## 11. Alternate / Error Flows

### Validation failures
- From > thru (P&L): block run; show inline message.
- Missing dates: block run; required field indicators.

### Concurrency conflicts / reproducibility
- If backend returns 409 conflict or a specific errorCode indicating stale report context:
  - UI shows banner: “Report context is no longer valid. Please rerun the report.”
  - UI keeps parameters and clears results.
- If backend provides `reportRunId/resultHash`, UI must use it for drilldown and export to ensure the export matches the displayed report.

### Unauthorized access
- Navigating directly to route without permission results in Access Denied screen.
- If permissions revoked mid-session and a call returns 403, UI clears current results and shows Access Denied.

### Empty states
- No posted lines for parameters: show “No data available for selected period/as-of date.”
- Drilldown returns empty list: show “No underlying entries for this selection.”

### Service unavailable
- Show retry; display trace/request id if provided by backend response headers/body.

## 12. Acceptance Criteria

### Scenario 1: Generate Profit & Loss for a date range
**Given** the user has permission `accounting:reports:financial-statements:view`  
**And** posted ledger/journal lines exist for the selected date range  
**When** the user selects “Profit & Loss” and enters a valid From date and Thru date  
**And** clicks “Run Report”  
**Then** the system displays a P&L statement generated from posted ledger lines only  
**And** each statement line shows an amount formatted using the backend-provided `currencyUomId`  
**And** the URL query params reflect the report parameters (`reportType`, `from`, `thru`)

### Scenario 2: Generate Balance Sheet as of a date
**Given** the user has permission `accounting:reports:financial-statements:view`  
**And** posted ledger/journal lines exist up to the selected as-of date  
**When** the user selects “Balance Sheet” and enters an as-of date  
**And** clicks “Run Report”  
**Then** the system displays a Balance Sheet as of that date generated from posted ledger lines only  
**And** the URL query params reflect the report parameters (`reportType`, `asOf`)

### Scenario 3: Validate invalid date range for P&L
**Given** the user is on the Profit & Loss report screen  
**When** the user enters a From date after the Thru date  
**And** attempts to run the report  
**Then** the UI prevents the request from being sent  
**And** displays an inline validation message indicating the date range is invalid

### Scenario 4: Drilldown from statement line to accounts
**Given** a financial statement is loaded  
**And** the user has permission `accounting:reports:financial-statements:drilldown`  
**And** at least one statement line is drilldown-enabled  
**When** the user clicks a drilldown-enabled statement line  
**Then** the system displays the contributing GL accounts and their amounts for that same report context  
**And** the user can navigate back to the statement lines without losing the report parameters

### Scenario 5: Drilldown from account to journal/ledger lines
**Given** the user is viewing the contributing accounts for a statement line  
**And** the user has permission `accounting:reports:financial-statements:drilldown`  
**When** the user selects a specific GL account  
**Then** the system displays the posted journal/ledger lines contributing to that account balance for the report context  
**And** each line includes at least one source reference identifier (`journalEntryId` preferred, else `ledgerEntryId`, else `eventId` if provided)

### Scenario 6: Drilldown to source event reference (if provided)
**Given** the user is viewing journal/ledger lines for a GL account  
**When** the user selects a line that includes an `eventId`  
**Then** the system displays source event identifiers (event id and type at minimum)  
**And** the system displays `payloadSummary` if provided  
**And** the system does not display raw payload JSON unless the user has permission `accounting:events:view-payload`

### Scenario 7: Export a generated statement
**Given** the user has permission `accounting:reports:financial-statements:export`  
**And** a financial statement is loaded  
**When** the user clicks “Export” and selects an available export format  
**Then** the system downloads or provides a download link for the exported report  
**And** the exported content corresponds to the on-screen report context (same `reportRunId`/`resultHash` and parameters)

### Scenario 8: Unauthorized user cannot access financial statements
**Given** the user does not have permission `accounting:reports:financial-statements:view`  
**When** the user navigates to the Financial Statements route  
**Then** the system shows an Access Denied screen  
**And** no financial statement data is displayed

### Scenario 9: No data for selected period
**Given** the user has permission `accounting:reports:financial-statements:view`  
**And** there are no posted ledger/journal lines for the selected parameters  
**When** the user runs the report  
**Then** the system shows a “No data available for the selected period/as-of date” empty state  
**And** does not show an error

### Scenario 10: Trace context propagation
**Given** the user runs a report or drilldown  
**When** the frontend sends the request to the backend  
**Then** the request includes `traceparent` (and `tracestate` if present) headers unchanged if already present  
**And** if `traceparent` is absent, the frontend generates one and includes it (AD-008)

## 14. Non-Functional UI Requirements

- **Performance:** Use server-side pagination for journal/ledger line drilldown if dataset is large; do not fetch full payloads for list rows. Target: first statement results visible within ~3 seconds for typical periods (SLA not guaranteed; show loading states).
- **Accessibility:** Keyboard navigable drilldown (tab/enter), proper table semantics, ARIA labels for expandable/drilldown controls; errors announced via aria-live.
- **Responsiveness:** Usable on tablet width; tables allow horizontal scroll when needed.
- **i18n/timezone/currency:**
  - Dates displayed in user locale; query params use ISO `YYYY-MM-DD`.
  - Currency formatting uses backend-provided `currencyUomId`; UI must not assume a default currency.
