## 2. Story Intent

### As a / I want / So that
- **As a** Service Advisor / Front Desk user  
- **I want** to create a new **Draft** estimate for a selected Customer and Vehicle  
- **So that** I can start building a quote and route to the estimate workspace with the newly created estimate identifier.

### In Scope
- UI flow to select Customer and Vehicle (via navigation to existing customer/vehicle screens if needed).
- Create Draft Estimate action (frontend → Moqui screen transition/service → backend) and routing to estimate editor/workspace on success.
- Display created estimate identifier and status (Draft).
- Permission/authorization handling for estimate creation attempts.
- User-visible confirmation + error messaging.
- Audit visibility requirements (show created/updated metadata that backend returns; do not invent audit storage).
- Idempotency handling for create to prevent duplicates on double-submit/retry (DECISION-INVENTORY-012).

### Out of Scope
- Estimate approval workflow (methods, signatures, decline/reopen) beyond creating the initial Draft.
- Work order creation/conversion.
- Adding parts/labor line items (only navigate to workspace where that will occur).
- Configuring shop/location defaults, currency, tax region (configuration ownership is outside this story).
- Implementing backend persistence or audit generation (frontend consumes).
- Time entry / technician timekeeping (explicitly not workexec-owned; DECISION-INVENTORY-009).

  - Estimate identifier (`estimateNumber` preferred; fallback `estimateId`)

## 11. Alternate / Error Flows

### Validation failures (client-side)
- Missing `customerId`: prevent submit; show “Select a customer.”
- Missing `vehicleId`: prevent submit; show “Select a vehicle.”

### Validation failures (server-side 400)
- Show backend-provided `message`.
- If `fieldErrors` present, show inline per field.
- Keep selections intact for correction and retry.

### Concurrency / duplicate / idempotency
- Double-click submit:
  - UI disables submit and sends only one request.
- Retry after timeout:
  - UI reuses the same `Idempotency-Key` for the same attempt; backend should return the same outcome (DECISION-INVENTORY-012).
- If backend returns 409 with `existingResourceId`:
  - UI offers “Open existing estimate” action that navigates to `EstimateEdit` for that id.

### Unauthorized access (403)
- If capability signal indicates no permission:
  - Hide/disable create action.
- If backend returns 403:
  - Show access denied message; remain on create screen; do not retry automatically.

### Not found (404)
- Show “Customer or vehicle not found.”
- Provide action to re-open selector and clear invalid selection.

### Empty states
- If customer/vehicle search returns no results:
  - Show empty-state guidance and CTA to create new customer/vehicle (navigation only; creation is outside this story).

## 12. Acceptance Criteria

### Scenario 1: Create draft estimate successfully
**Given** the Service Advisor is authenticated  
**And** the user has permission/capability to create estimates  
**And** a Customer is selected with `customerId`  
**And** a Vehicle is selected with `vehicleId`  
**When** the user clicks “Create Estimate”  
**Then** the system sends a create-estimate request containing `customerId` and `vehicleId`  
**And** the request includes an `Idempotency-Key` header  
**And** on success the UI routes to `durion-workexec/EstimateEdit` for the returned `estimateId`  
**And** the Estimate workspace displays the estimate status as Draft  
**And** the estimate identifier (`estimateNumber` or fallback `estimateId`) is visible.

### Scenario 2: Prevent creation when customer is missing
**Given** the user is on the Create Estimate flow  
**And** no Customer is selected  
**When** the user attempts to create an estimate  
**Then** the UI must block submission  
**And** the UI must indicate that Customer is required  
**And** no create-estimate request is sent.

### Scenario 3: Prevent creation when vehicle is missing
**Given** the user is on the Create Estimate flow  
**And** a Customer is selected  
**And** no Vehicle is selected  
**When** the user attempts to create an estimate  
**Then** the UI must block submission  
**And** the UI must indicate that Vehicle is required  
**And** no create-estimate request is sent.

### Scenario 4: Handle backend validation error (400) with field errors
**Given** the user selected a customer and vehicle  
**When** the create-estimate request is submitted  
**And** the backend responds with HTTP 400 and a standard error envelope containing `fieldErrors`  
**Then** the UI must remain on the creation screen  
**And** the UI must display the envelope `message`  
**And** the UI must display each `fieldErrors` entry inline on the corresponding field when possible  
**And** the user must be able to correct the issue and retry.

### Scenario 5: Handle unauthorized attempt (403)
**Given** the user is authenticated  
**When** the user submits a create-estimate request  
**And** the backend responds with HTTP 403  
**Then** the UI must not navigate to the estimate workspace  
**And** the UI must display an access denied message  
**And** the UI must surface `correlationId` if provided (without displaying PII).

### Scenario 6: Handle not found (404)
**Given** the user selected a customerId or vehicleId that no longer exists  
**When** the create-estimate request is submitted  
**And** the backend responds with HTTP 404  
**Then** the UI must show a “not found” message  
**And** the UI must prompt the user to re-select the missing record  
**And** the UI must not navigate away.

### Scenario 7: Retry uses same Idempotency-Key
**Given** the user clicked “Create Estimate” and the request timed out client-side  
**When** the user clicks “Retry” for the same create attempt  
**Then** the UI must resend the create-estimate request with the same `Idempotency-Key` as the timed-out attempt  
**And** if the backend returns success, the UI navigates to the created estimate workspace  
**And** if the backend returns 409 with `existingResourceId`, the UI offers navigation to that estimate.
