## Issue Body

## 1. Story Header

### Title
[FRONTEND] [STORY] Pricing: Define Base Company Price Books & Price Book Rules (Moqui Admin Screens)

### Primary Persona
Pricing Analyst / Pricing Administrator

### Business Value
Enable consistent, auditable company-wide pricing configuration (price books + effective-dated rules) so downstream quoting uses deterministic rule evaluation with controlled variation by location and customer tier.

---

## 2. Story Intent

### As a / I want / So that
**As a** Pricing Analyst (authorized pricing admin),  
**I want** to create and manage PriceBooks and their effective-dated PriceBookRules (global/category/SKU targeting, single-dimension rule conditions, scoped books for combined scope),  
**so that** pricing is consistent across stores, deterministically evaluated, and all changes are auditable.

### In-scope
- Moqui admin UI to:
  - List/search PriceBooks (including base/company-default and scoped books)
  - View a PriceBook and its Rules
  - Create/update/end-date (“deactivate”) PriceBooks (within allowed fields)
  - Create/update/end-date (“deactivate”) PriceBookRules with effective dating, priority, and targeting
  - View audit history for PriceBook and PriceBookRule changes (read-only)
- Frontend validation aligned to Pricing domain decisions:
  - Effective dating uses store-local timezone semantics and date-time pickers (DECISION-PRICING-003)
  - PriceBook scope model: optional `locationId`, optional `customerTierId`, required `currencyUomId` (DECISION-PRICING-004)
  - Rule condition model: at most one condition dimension per rule; combined scenarios modeled via scoped books (DECISION-PRICING-005)
  - Deactivation via `effectiveEndAt` (DECISION-PRICING-016)
- Integration wiring from Moqui screens/forms to backend Pricing endpoints under `/pricing/v1/...` (DECISION-PRICING-002)

### Out-of-scope
- Price quote calculation UI (Workexec “PriceQuote” consumer flows)
- Promotions and restriction rules/overrides admin UIs
- Building/maintaining product identity, SKU/name, UOM catalog (Inventory owns product identity; DECISION-PRICING-017)
- Defining pricing math/rounding in UI (backend-owned; DECISION-PRICING-001)

- Deep links (screen paths must follow repo conventions; see Open Questions):
  - PriceBook list
  - PriceBook detail (with Rules + Audit)
  - Rule create/edit (within a book)

### Screens to create/modify (Moqui)
Create screens under the Pricing admin area, matching the nearest existing admin screen pattern (DECISION-PRICING-015):
- `screens/pricing/admin/PriceBookList.xml`

### Navigation context
- List → select a PriceBook → tabs/sections:
  - **Rules**
  - **Details**
  - **Audit**
- Rule edit is reachable from Rules section (Create) and from a rule row (View/Edit).

### User workflows (happy + alternate paths)

**Happy path: create a scoped price book and add a rule**
1. Navigate to Price Books list.
2. Click “Create Price Book”.
3. Enter name, select currency, optionally select location and/or customer tier scope.
4. Save → book appears in list.
5. Open book → Rules → “Add Rule”.
6. Select target type (GLOBAL / CATEGORY / SKU).
7. Select target (if not GLOBAL) via picker.
8. Enter `pricingLogic` JSON (validated by backend; UI only validates shape minimally).
9. Optionally set a single rule condition dimension (NONE / LOCATION / CUSTOMER_TIER) per rule (DECISION-PRICING-005).
10. Set priority and effective start/end (date-time).
11. Save → rule appears in Rules table.
12. Audit tab shows create entries.

**Alternate path: model combined location+tier**
- Create a PriceBook with both `locationId` and `customerTierId` set (DECISION-PRICING-004).
- Add rules with `conditionType=NONE` (or single-dimension conditions if needed, but not both).

**Alternate path: deactivate (end-date)**
- From book or rule row: “Deactivate” prompts for an end date-time (default to “now” in store timezone) and sets `effectiveEndAt` (DECISION-PRICING-016).

**Alternate path: view audit**
- From book detail → Audit tab → view timeline/list of changes for the book and its rules.

**PriceBook list**

  - customerTierId (optional)
  - isDefault (boolean; if supported by backend)
  - effectiveStartAt (optional if backend supports; otherwise omit)

**Rules table (within PriceBook detail)**
- Columns (minimum):
  - targetType
  - target (resolved label)
  - condition (type + resolved label)
  - priority
  - effectiveStartAt
  - effectiveEndAt
  - derived status (Active/Inactive as-of now)
- Row actions:
  - View/Edit (manage permission only for edit)
  - Deactivate (manage permission only)

**Rule editor**
- Target selection:
  - GLOBAL: no target picker
  - SKU: product picker (Inventory search; DECISION-PRICING-017)

- Save/cancel transitions:
  - Save calls create/update endpoint

### State changes

  - Existing record updated if not ended/immutable and user has manage permission
- Deactivate:
  - Sets `effectiveEndAt` (DECISION-PRICING-016)
- UI must treat ended records as immutable by default and require creating a new effective-dated record for changes (DECISION-PRICING-018 pattern applied to effective-dated immutability; see Open Questions for exact backend enforcement on rules/books).

### Service interactions
- Pricing:
  - list/get/create/update/end-date PriceBooks

## 7. Business Rules (Translated to UI Behavior)

### Validation (client-side, mirrored server-side)
- IDs are opaque; UI must not parse or infer meaning.
- PriceBook (DECISION-PRICING-004):
  - `name` required
  - `currencyUomId` required (single-currency per book)
  - `locationId` optional
  - `customerTierId` optional
  - Combined scope is represented by setting both `locationId` and `customerTierId` (no special composite scope field) (DECISION-PRICING-004).
- PriceBookRule:
  - `priceBookId` required
  - `targetType` required; allowed values include `SKU`, `CATEGORY`, `GLOBAL` (DECISION-PRICING-006 specificity model references these)
  - If `targetType != GLOBAL`, `targetId` required
  - `pricingLogic` required; UI validates only that it is valid JSON and includes `type` key; backend validates schema (DECISION-PRICING-006)
  - Condition model: at most one of LOCATION or CUSTOMER_TIER or NONE (DECISION-PRICING-005)
  - `priority` required integer (UI does not assume range)
  - `effectiveStartAt` required
  - If `effectiveEndAt` provided: must be strictly after `effectiveStartAt` for half-open interval semantics `[start, end)` (DECISION-PRICING-003)
- Deactivation:
  - Prefer end-dating via `effectiveEndAt`; status is derived for display/filtering (DECISION-PRICING-016)

### Enable/disable rules
- Disable target picker when targetType = GLOBAL.
- Disable condition value picker when conditionType = NONE.
- Disable Save and all editable fields when record is immutable (ended effective window) unless user has an explicit historical-manage permission (if supported; see Open Questions).
- Hide create/edit/deactivate actions when user lacks manage permission; still allow view screens with view permission (DECISION-PRICING-015).

### Visibility rules
- Show store timezone context near effective date-time fields (DECISION-PRICING-003).
- Do not show multi-condition UI (no simultaneous location + tier condition on a rule) (DECISION-PRICING-005).
- If backend returns audit/history, show Audit tab; if not available, show “History not available” empty state (DECISION-PRICING-015).

### Error messaging expectations
- 400 validation errors:
  - Render field-level errors when `fieldErrors` map is provided.
  - Render form-level banner when only `message` is provided.
- 409 conflict:
  - Show actionable banner: “Conflict: this record was changed or overlaps an existing effective-dated record.”
  - If backend provides conflicting record identifiers, list them as links to view.
- 403:
  - Show unauthorized page/state; do not leak entity data.
- 5xx/network:
  - Show retry banner; preserve unsaved form state.

### Fields (type, required, defaults)

#### PriceBook (frontend contract)
- `priceBookId` (string/UUID, read-only)
- `name` (string, required)
- `currencyUomId` (string, required) (DECISION-PRICING-004)
- `locationId` (string/UUID, optional) (DECISION-PRICING-004)

#### PriceBookRule (frontend contract)
- `ruleId` (string/UUID, read-only)
- `priceBookId` (string/UUID, required; hidden when editing within a book)

- `targetId` (string/UUID, required unless GLOBAL)

- `conditionValue` (string/UUID, required if conditionType != NONE)
- `priority` (integer, required)
- `effectiveStartAt` (timestamp, required)
- `effectiveEndAt` (timestamp, optional)
- Audit/display:
  - `createdAt`, `createdBy` (read-only)
  - `updatedAt`, `updatedBy` (read-only)

Read-only vs editable by state/role

- Manage permission: can create/update/deactivate.
- Ended records: read-only by default; if backend supports elevated historical edit permission, UI must gate it explicitly and show a warning banner (see Open Questions).

Derived/calculated fields (UI)
- Target label:
  - GLOBAL → “Global”
  - SKU → resolved product `sku — name`
  - CATEGORY → resolved category name
- Condition label:
  - NONE → “None”
  - LOCATION → resolved location name
  - CUSTOMER_TIER → resolved tier name
- Pricing logic summary:
  - Display a short summary derived from `pricingLogic.type` and common fields if present; otherwise display `type` only. UI must not compute money.

## 9. Service Contracts (Frontend Perspective)

> All Pricing endpoints are under `/pricing/v1/...` (DECISION-PRICING-002). Exact endpoint names for PriceBook/Rule CRUD are not defined in the provided domain rules; this story defines required frontend-facing contracts and leaves exact routes as Open Questions.

### Load/view calls
- `GET /pricing/v1/price-books`
  - Query: `page`, `pageSize`, optional filters: `currencyUomId`, `locationId`, `customerTierId`, `activeAsOf`
  - Response: `{ items: PriceBookSummary[], total: number }`
- `GET /pricing/v1/price-books/{priceBookId}`
  - Response: `PriceBook`
- `GET /pricing/v1/price-books/{priceBookId}/rules`
  - Query: `page`, `pageSize`, optional filters: `targetType`, `activeAsOf`
  - Response: `{ items: PriceBookRuleSummary[], total: number }`
- `GET /pricing/v1/price-book-rules/{ruleId}`
  - Response: `PriceBookRule`
- Product lookup (Inventory; DECISION-PRICING-017):
  - `GET /inventory/v1/products?query=<text>&page=<n>&pageSize=<n>`
  - Response includes `productId`, `sku`, `name`

### Create/update calls
- `POST /pricing/v1/price-books`
  - Body: create fields
  - Response: created `PriceBook`
- `PUT /pricing/v1/price-books/{priceBookId}`
  - Body: updatable fields (backend-owned)
  - Response: updated `PriceBook`
- `POST /pricing/v1/price-books/{priceBookId}/rules`
  - Body: create fields
  - Response: created `PriceBookRule`
- `PUT /pricing/v1/price-book-rules/{ruleId}`
  - Body: updatable fields
  - Response: updated `PriceBookRule`
- Deactivate/end-date (DECISION-PRICING-016):
  - Preferred: `POST /pricing/v1/price-book-rules/{ruleId}:end-date` with `{ effectiveEndAt }`
  - Or: `PUT /pricing/v1/price-book-rules/{ruleId}` with `effectiveEndAt` set
  - UI must follow backend contract once confirmed.

### Submit/transition calls
- None required beyond create/update/end-date.

### Error handling expectations
- 400:
  - `{ errorCode: "VALIDATION_ERROR", message, fieldErrors?: { [field]: string } }`
- 409:
  - `{ errorCode: "CONFLICT", message, conflictingIds?: string[] }`
- 403:
  - `{ errorCode: "FORBIDDEN" }`
- UI must not log sensitive fields; pricing logic JSON may contain internal metadata and must be treated as potentially sensitive (DECISION-PRICING-014 pattern).

## 10. State Model & Transitions

### Allowed states
Effective-dated status is derived (DECISION-PRICING-016):
- Derived ACTIVE if now (store-local) is within `[effectiveStartAt, effectiveEndAt)` (or end is null)
- Derived INACTIVE otherwise

### Role-based transitions
- With manage permission:
  - Create PriceBook / Rule
  - Update PriceBook / Rule (if not ended/immutable)
  - End-date (deactivate) PriceBook / Rule
- With view permission:
  - View list/detail/audit only

### UI behavior per state
- Derived INACTIVE:
  - Show as inactive in lists
  - Allow viewing
  - Allow editing only if record is not ended and backend allows (typically inactive due to future start may still be editable)
- Ended (effectiveEndAt in the past):
  - Treat as immutable by default; disable edits and show guidance to create a new version.

## 11. Alternate / Error Flows

### Validation failures
- Missing required fields → prevent submit; highlight fields.
- Invalid JSON in `pricingLogic` → block submit with inline error.
- `effectiveEndAt <= effectiveStartAt` → inline error on end date-time field (half-open interval; DECISION-PRICING-003).

### Concurrency conflicts
- If backend uses optimistic locking/versioning:
  - On 409, show “This record changed since you loaded it.”
  - Provide actions: “Reload” and “Copy my changes” (best-effort client-side; no auto-merge).
  - Do not show success toast.

### Unauthorized access
- If user lacks view permission:
  - Block navigation and show unauthorized page/state.
- If user has view but not manage:
  - Hide manage actions.
  - Direct navigation to edit URLs shows read-only view with a banner “You do not have permission to edit.”

### Empty states
- No price books:
  - Show empty state with “Create Price Book” CTA only if manage permission.
- No rules in a book:
  - Show empty state with “Add Rule” CTA only if manage permission.

And a rule exists with no `effectiveEndAt`  
When I choose “Deactivate” and set an end date-time

When I attempt to save a rule and the backend responds with HTTP 409 and `errorCode="CONFLICT"`  
Then the UI shows a conflict banner with the backend message
