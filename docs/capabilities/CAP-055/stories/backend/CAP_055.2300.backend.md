## Business rules and invariants
- Tenancy (§3 preamble, ADR-0062 §9): `tenant_id uuid DEFAULT public.app_current_tenant() NOT NULL`, RLS ENABLE + FORCE with `tenant_isolation`, `UNIQUE (tenant_id, <pk>)`, composite FKs `(tenant_id, …)` — including the new self-FK `replaces_match_id` and the adjustment FKs `settles_match_id`, `bridges_statement_id`; every entity `extends TenantScopedEntity`; no new row in `db/tenancy-global-tables.txt`; no entity or business-unit column (D6).
- Identity (AD-006, ADR-0013): every id UUIDv7 via `@GeneratedValue` + `@UUIDv7Id`; DTO ids stay `UUID`-typed.
- U1, U2 (§3.1), U3, U4 (§3.2), O1 (§3.6) — delivered here as database constraints; the service checks that surface them as error codes arrive with S2 (U1/U2/U3) and S4 (U4/O1).
- Behaviour preservation (§6.4 "Which story lands what", §3.5, §7.1): the new `bank_reconciliation_adjustment` columns are nullable and no link CHECK, `TRANSFER` value or bridge unique is added here, so the F2 adjustment request (`type`, `amount`, `description`) posts exactly as today until S4.
- M7 "matches are never deleted" (§3.4) — the moved service honours it from commit 2 (behaviour 3).
- R3 "amounts are stored exactly as delivered" (§3.2) — the conversion copies `amount` unchanged into `signed_amount` numeric(19,4).
- `@Version` on `bank_reconciliation`, `bank_import`, `bank_transaction`; stale version → 409 `OPTIMISTIC_LOCK` (§6.3, ADR-0017 §2 version class).

## Alternate and error flows
- Alpha databases are recreated from the baseline, so no `bank_reconciliation_line` rows exist to convert; under a versioned migration they are converted as above and a reconciliation with no lines yields a synthetic statement with `activity_total = 0`.
- An existing `gl_match` group with members on both sides > 1 → migration aborts with the group's `match_id` in the error (no data invented).
- `btree_gist` cannot be created (privilege) → migration fails; the exclusion constraint is never silently dropped.
- Stale `version` on save → 409 `OPTIMISTIC_LOCK` (`ApiError` envelope, ADR-0017 §3).
- A `..bankrec..` class importing `..bankfeed..`, or a format library imported outside `..bankfeed.file..` → build fails in `ArchitectureTest`/`DomainWallsTest`.
- Seed re-run → idempotent upsert keyed on `account_code` (`R__seed_reference_accounting.sql` l.11-19); the flag flips to TRUE on existing tenants.
- F2 `POST /{id}/adjustments` with `type = OTHER` and no link or justification → posts as today (no link CHECK until S4, §6.4).
