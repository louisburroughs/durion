## Story Intent
**As a** backend engineer on `pos-accounting` **I want** the delivered F2 bank-reconciliation code relocated to `internal/bankrec/`, the §6.4 schema in place in the flattened baseline (new tables, altered `bank_reconciliation*`, `bank_reconciliation_line` removed), `@Version` on the aggregates, a thin `bank_account_profile`, the `1000 Cash` seed corrected and the core-versus-adapter ArchUnit walls enforced **so that** S2–S6 build on one package layout and one schema, and no later story can leak a file format or a provider into the reconciliation core.

## Business rules and invariants
- Tenancy (§3 preamble, ADR-0062 §9): `tenant_id uuid DEFAULT public.app_current_tenant() NOT NULL`, RLS ENABLE + FORCE with `tenant_isolation`, `UNIQUE (tenant_id, <pk>)`, composite FKs `(tenant_id, …)`; every entity `extends TenantScopedEntity`; no new row in `db/tenancy-global-tables.txt`.
- Identity (AD-006, ADR-0013): every id UUIDv7 via `@GeneratedValue` + `@UUIDv7Id`; DTO ids stay `UUID`-typed.
- U1, U2 (§3.1), U3, U4 (§3.2), O1 (§3.6) — delivered here as database constraints; the service checks that surface them as error codes arrive with S2 (U1/U2/U3) and S4 (U4/O1).
- M7 "matches are never deleted" (§3.4) — the moved service honours it from commit 2 (behaviour 3).
- R3 "amounts are stored exactly as delivered" (§3.2) — the conversion copies `amount` unchanged into `signed_amount` numeric(19,4).
- `@Version` on `bank_reconciliation`, `bank_import`, `bank_transaction`; stale version → 409 `OPTIMISTIC_LOCK` (§6.3, ADR-0017 §2 version class).

## Alternate and error flows
- Alpha databases are recreated from the baseline, so no `bank_reconciliation_line` rows exist to convert; under a versioned migration they are converted as above and a reconciliation with no lines yields a synthetic statement with `activity_total = 0`.
- An existing `gl_match` group with members on both sides > 1 → migration aborts with the group's `match_id` in the error (no data invented).
- `btree_gist` cannot be created (privilege) → migration fails; the exclusion constraint is never silently dropped.
- Stale `version` on save → 409 `OPTIMISTIC_LOCK` (`ApiError` envelope, ADR-0017 §3).
- A `..bankrec..` class importing `..bankfeed..`, or a format library imported outside `..bankfeed.file..` → build fails in `ArchitectureTest`/`DomainWallsTest`.
- Seed re-run → idempotent upsert keyed on `account_code` (`R__seed_reference_accounting.sql` l.11-19); the flag flips to TRUE on existing tenants.

## Acceptance criteria
1. **Given** the F2 suites `BankReconciliationServiceTest`, `BankReconciliationGuardsAndViewsTest`, `BankReconciliationControllerTest` **When** commit 1 is applied **Then** they pass with only package/import edits (§2.1 rename-only commit).
2. **Given** commit 2 **When** `POST /import`, `GET /{id}`, `POST /{id}/match`, `/unmatch`, `/adjustments`, `/finalize`, `/report`, `/audit` are exercised by the controller tests **Then** every status code, error code and response body is unchanged (§1.1 API row; §7.1 S1 "behaviour-preserving").
3. **Given** the edited baseline **When** Flyway runs on an empty Testcontainers Postgres **Then** every §6.4 table, column, check, partial unique and the exclusion constraint exist and `bank_reconciliation_line` does not; **Given** the change ships as a versioned migration instead **Then** the conversion fixture proves every line has exactly one `bank_transaction` with the same date, amount, description and reference and every match group has one `ACCEPTED` header with `active` members (§6.4).
4. **Given** the new tables **When** `TenancySchemaConformanceIT` runs **Then** each has the `tenant_id` default, RLS ENABLE + FORCE, the `tenant_isolation` policy and `UNIQUE (tenant_id, pk)`; none is listed in `db/tenancy-global-tables.txt` (ADR-0062 §9, §6.4).
5. **Given** two COMMITTED `bank_statement` rows on one account with windows 09-01..09-30 and 09-15..10-14 inserted directly **When** the second insert commits **Then** the exclusion constraint refuses it (U2, §8.2 [M]).
6. **Given** two `gl_match` rows on the same `gl_line_id` **When** both are `active` **Then** the partial unique refuses the second; **When** the first is `active = false` **Then** the second is accepted (U4, §3.4 "history survives unmatch").
7. **Given** the seed **When** applied **Then** `1000 Cash` has `reconcilable = TRUE` and `account_subtype = BANK_CASH`; `1090` unchanged (G7, §4.1).
8. **Given** a test class in `..bankrec.service..` that imports a type from `..bankfeed.file..` **When** ArchUnit runs **Then** `ArchitectureTest` and `DomainWallsTest` fail (§2.1, §8.4 [M]).
9. **Given** two concurrent saves of one `bank_reconciliation` with the same `version` **When** the second commits **Then** 409 `OPTIMISTIC_LOCK` (§6.3).
