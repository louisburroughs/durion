## Issue Body

## 1. Story Header

### Title
[FRONTEND] [STORY] Location Admin (Read-only): View Sync’d Locations Roster & Location Sync Logs (durion-hr → Location Replica)

### Primary Persona
System Administrator / Pricing Administrator (POS backoffice user)

### Business Value
Provide a read-only UI to verify which locations exist locally (synced replicas), their active/inactive status, and the latest sync outcomes, so admins can confidently scope pricing overrides to valid locations and quickly diagnose sync issues without backend access.

---

## 2. Story Intent

### As a / I want / So that
- **As a** System Administrator / Pricing Admin  
- **I want** to view the locally synced location roster (id, name, status, optional region/tags) and the most recent sync run logs  
- **So that** I can confirm pricing scope uses valid locations and I can troubleshoot sync failures without backend access.

### In-scope
- New/updated Moqui screens to:
  - List/search/filter the locally stored synced locations (replica) used for pricing scope validation.
  - View a location detail page (read-only) including status and metadata (region/tags if available).
  - View sync logs (list + detail).
- UI handling for empty/error states and unauthorized access.
- Moqui service interactions to load locations and sync logs.
- Default list filtering behavior per Location domain decisions (see Business Rules).

### Out-of-scope
- Implementing the actual sync job from `durion-hr` (backend story #53).
- Creating/updating locations from the UI (source-of-truth is `durion-hr` / sync process).
- Enforcing pricing override creation rules in UI flows unrelated to this roster (those belong to pricing UI stories).
- Building/altering pricing override screens (only roster/log visibility here).
- Any “rerun sync” or “repair sync” actions (unless a separate backend action exists and is explicitly scoped later).

## 7. Business Rules (Translated to UI Behavior)

### Read-only replica behavior
- Locations shown here are **replicated from `durion-hr`** and **not editable** in POS UI.
  - UI must render all location fields read-only and omit edit/create/deactivate actions.

### Status visibility and default filtering
- UI must clearly show `status` and allow filtering by it.
- **Default filter for Synced Locations list is `ACTIVE`** (DECISION-LOCATION-008).
- INACTIVE locations must remain discoverable via `INACTIVE` or `ALL` filter (do not hide permanently).

### Pricing eligibility note (informational only)
- If `status != ACTIVE`, UI displays helper text: “Inactive (not eligible for new pricing overrides).”
  - This is informational only; enforcement is out-of-scope and belongs to pricing stories.

### Tags and region rendering resilience
- `tags` may be returned as `string[]` or as a CSV string; UI must render both safely (DECISION-LOCATION-009).
- `region` is treated as display-only free text; UI must not enforce a controlled vocabulary (DECISION-LOCATION-009).
- Filtering by `region`/`tags` is only enabled if the backend explicitly supports it (no client-side “fake filtering” on partial datasets).

### Permission gating
- Read-only pages require `location:view` (DECISION-LOCATION-007).
- If the user lacks permission, backend returns 403; UI must show access denied and must not display partial data.

**Error messaging expectations**
- API errors must be surfaced:
  - “Unable to load synced locations. Try again.” / “Unable to load sync logs. Try again.”
- Unauthorized:
  - 401 → redirect to login (if app supports)
  - 403 → show “Access denied: location:view permission required.”

## 8. Data Requirements

### Entities involved (frontend-facing)
- `Location` (replica)
- `SyncLog` (sync run record)

### Fields

#### Location (replica)
- `locationId` (String; required; display; read-only)
- `name` (String; required; display; read-only)
- `status` (Enum/String; required; display; read-only; values include at least ACTIVE/INACTIVE)
- `region` (String; optional; display if present; read-only; display-only semantics per DECISION-LOCATION-009)
- `tags` (Either `List<String>` or CSV `String`; optional; display if present; read-only; render-resilient per DECISION-LOCATION-009)
- `createdAt` (Timestamp; optional; display on detail; read-only)
- `updatedAt` (Timestamp; optional; display on detail and optionally list; read-only)
- `version` (Number/String; optional; display optional; read-only; used for optimistic locking elsewhere but not required here)

#### SyncLog
- `syncId` (UUID/String; required; display; read-only)
- `syncStartedAt` (Timestamp; required; display; read-only)
- `syncFinishedAt` (Timestamp; optional if running; display; read-only)
- `status` (Enum/String: SUCCESS, PARTIAL_FAILURE, FAILURE; required)
- `recordsProcessed` (Integer; required)
- `recordsCreated` (Integer; required)
- `recordsUpdated` (Integer; required)
- `recordsSkipped` (Integer; required)
- `notes` (Text; optional)

### Read-only vs editable by state/role
- All fields in this story are **read-only** for all roles.

### Derived/calculated fields (UI-only)
- “Duration” = `syncFinishedAt - syncStartedAt` (only if both present).
- “Last sync status” badge on Synced Locations list header (derived from most recent SyncLog if included in list response or fetched separately).

## 12. Acceptance Criteria

### Scenario 1: View ACTIVE synced locations (default filter)
Given I am an authenticated user with `location:view` permission  
When I navigate to the Synced Locations list screen  
Then the list loads with default filter `status=ACTIVE`  
And I see a paginated list of synced locations with fields `locationId`, `name`, and `status`  
And locations with status `INACTIVE` are not shown while the ACTIVE filter is applied

### Scenario 2: View INACTIVE locations with eligibility note
Given I am viewing the Synced Locations list with status filter set to `INACTIVE`  
When the list loads  
Then each location row shows status `INACTIVE`  
And the UI displays an informational note that INACTIVE locations are not eligible for new pricing overrides

### Scenario 3: View location detail (read-only)
Given I am on the Synced Locations list  
When I select a location with locationId `loc-1`  
Then I am navigated to the Synced Location detail screen for `loc-1`  
And I see `locationId`, `name`, `status`, and any available `region`/`tags` as read-only fields  
And there are no edit, create, or deactivate actions on the page

### Scenario 4: Tags rendering supports array and CSV
Given I open a Synced Location detail record  
And the backend returns `tags` as an array of strings  
When the page renders  
Then the tags are displayed as a list of tag values without errors  
Given I open a Synced Location detail record  
And the backend returns `tags` as a comma-separated string  
When the page renders  
Then the tags are displayed as a list split on commas (trimmed) without errors

### Scenario 5: View sync logs list (default ALL) and sorting
Given I am an authenticated user with `location:view` permission  
When I navigate to the Location Sync Logs list screen  
Then the list loads with default filter `status=ALL`  
And I see sync runs sorted by `syncStartedAt` descending  
And each entry shows `status` and record counts (`recordsProcessed`, `recordsCreated`, `recordsUpdated`, `recordsSkipped`)

### Scenario 6: View sync log detail
Given I am on the Sync Logs list  
When I open a sync log entry  
Then I see `syncStartedAt`, `syncFinishedAt`, `status`, counts, and `notes` (if present)  
And if both timestamps are present, I see a derived “Duration” value

### Scenario 7: Handle backend failure with retry
Given the backend service is unavailable  
When I load the Synced Locations list screen  
Then I see an error state indicating locations could not be loaded  
And I can retry the request from the UI  
Given the backend service is unavailable  
When I load the Location Sync Logs list screen  
Then I see an error state indicating sync logs could not be loaded  
And I can retry the request from the UI

### Scenario 8: Unauthorized access
Given I am not authenticated  
When I navigate to the Synced Locations list or Sync Logs screens  
Then I am redirected to login or shown a session expired message (401 handling)  
Given I am authenticated but lack `location:view` permission  
When I navigate to the Synced Locations list or Sync Logs screens  
Then I see an access denied message (403 handling)  
And no location or sync log data is displayed

### Scenario 9: Not found on detail routes
Given I navigate directly to `/admin/location/synced-locations/does-not-exist`  
And the backend returns 404  
When the page renders  
Then I see a “Location not found” message and a link back to the Synced Locations list

And the backend returns 404  
When the page renders
