## Issue Body

## 1. Story Header

**Title**  
[FRONTEND] [STORY] Vehicle: Vehicle Lookup by VIN/Unit/Plate (Search + Select Snapshot)

**Primary Persona**  
Service Advisor

**Business Value**  
Reduce time and errors when identifying the correct customer asset so the advisor can start an estimate/workflow on the correct vehicle with owner context.

---

## 2. Story Intent

**As a** Service Advisor  
**I want** to search vehicles by VIN, unit number, or license plate (supporting partial search) and select a result  
**So that** I can quickly confirm the right vehicle and load a full vehicle + owner snapshot to begin an estimate.

### In-scope
- A dedicated vehicle lookup UI reachable from the POS workflow.
- Search by a single free-text query that matches VIN, unit number, or license plate.
- Display results with owner account context.
- Selecting a result loads “full vehicle + owner snapshot” and returns to the calling context in a deterministic way.
- Error/empty/loading states, input validation, and accessibility.
- Server-side pagination support (page index/size + total) and basic sorting (as supported by backend).

### Out-of-scope
- Creating/editing vehicles, owners, or contacts (CRM is SoR; this story is lookup/select only).
- Vehicle deduplication/merge flows.
- Implementing estimate creation itself (only integration handoff).
- Any operator actions on integration logs (not part of this story).
- Defining backend ranking algorithm beyond displaying backend-provided match metadata (if present).

---

## 3. Actors & Stakeholders

- **Service Advisor (end user):** Performs search and selection at counter/in shop intake.
- **Workexec (downstream workflow):** Consumes selected `vehicleId` (and optionally `partyId`) to initialize estimate context.
- **CRM domain services (backend):** Executes vehicle search and returns vehicle snapshot DTOs.
- **Security/RBAC policy owners:** Define which roles/scopes can view vehicle and owner/account data in POS.

## 6. Functional Behavior

### Triggers
- User submits search form (Enter key or Search button).
- User changes page (next/prev) or page size (if enabled).
- User selects a vehicle from results.

### UI actions
- Search input:
  - Single text field `query` (bound to URL param `q`).
  - Search button disabled until minimum length requirement met (see Business Rules).
- Results list:
  - Each row shows (all display-only):
    - Vehicle descriptor (year/make/model if provided; else unit/plate; else “Vehicle <masked id>”)
    - VIN (displayed; masking rules apply)
    - Unit number
    - License plate (masking rules apply)
    - Owner name (party display name)
    - Optional match metadata: `matchType` and `rankScore` (display-only if present)
  - “Select” action per result row.
- Pagination:
  - Show current page and total results.
  - Page navigation triggers a new search call with `pageIndex`/`pageSize`.

### State changes (frontend)
- `idle` → `searching` → `showingResults | empty | error`
- On selection: `loadingSnapshot` → `completed | snapshotError`
- Selected vehicle context is not persisted beyond redirect parameters.

### Service interactions (Moqui-oriented)
- Search submit calls a Moqui REST endpoint (implemented by Moqui screen/controller calling a CRM service) that proxies to CRM search.
- Selection calls a Moqui REST endpoint that proxies to CRM snapshot retrieval.
- Both calls must handle:
  - `400` invalid input (query too short/invalid)
  - `403` forbidden
  - `404` not found (snapshot)
  - `409` conflict (if returned by backend)
  - `5xx` server errors
- Correlation headers:
  - Moqui injects/propagates `X-Correlation-Id` and `traceparent` server-side (DECISION-INVENTORY-004).

## 7. Business Rules (Translated to UI Behavior)

### Validation
- `query` is required (trimmed non-empty).
- Minimum query length is **3 characters** (DECISION-INVENTORY-013).
  - UI disables Search until `query.trim().length >= 3`.
  - If user bypasses (e.g., manual request), backend 400 is shown as field error.
- Matching rules are backend-owned; UI does not implement contains/startsWith logic. UI labels the field as “VIN / Unit / Plate” and does not promise specific matching beyond “search”.

### Enable/disable rules
- Disable Search button when:
  - `query.trim().length < 3`
  - request in-flight (`searching`)
- Disable Select actions when:
  - snapshot load in-flight (`loadingSnapshot`)
  - OR row is being selected (prevent double-click)

### Visibility rules
- Results area visible after first search attempt.
- Empty state visible when search returns 0 results.
- Error banner visible when service call fails; include retry action.
- If user lacks permission, show access denied state and hide results entirely.

### Error messaging expectations
- `400 QUERY_TOO_SHORT` or equivalent: show field-level error “Query must be at least 3 characters”.
- `400` other validation: show field-level error if `fieldErrors.query` exists; else banner.
- `403`: show “Access denied” without leaking whether a vehicle exists.
- `404` on snapshot: show “Vehicle not found. It may have been removed.” and return to results.
- `409`: show “Vehicle data changed. Please retry.” and allow reselect/reload.
- `5xx`/network: show generic error with retry; preserve query and last results if available.
- Security: UI must not render backend-provided strings as HTML (treat as plain text) (DECISION-INVENTORY-006).

#### Search response DTO (from Moqui)
- `items` (array, required; may be empty)
- `pageIndex` (int, required)
- `pageSize` (int, required)
- `total` (int, required)

Each `items[]` element (summary):
- `vehicleId` (UUID string, required)
- `vin` (string, optional; may be null/omitted based on permission/redaction)
- `unitNumber` (string, optional)
- `licensePlate` (string, optional; may be null/omitted based on permission/redaction)
- `ownerPartyId` (UUID string, optional; if backend can determine a primary owner)
- `ownerDisplayName` (string, optional)
- `year` (int, optional)
- `make` (string, optional)
- `model` (string, optional)
- `matchType` (string, optional; display-only) (DECISION-INVENTORY-013)
- `rankScore` (number, optional; display-only) (DECISION-INVENTORY-013)

#### Snapshot response DTO (from Moqui)
Minimum required for handoff:
- `vehicleId` (UUID string, required)
Optional but preferred:
- `ownerPartyId` (UUID string, optional)
- `ownerDisplayName` (string, optional)
- Additional snapshot sections are backend-owned; UI treats unknown fields as opaque and does not depend on them.

### Read-only vs editable
- All fields are read-only in this story.

### Derived/calculated fields (frontend)
- `displayVin` and `displayPlate`:
  - UI may mask in display (e.g., show last 6–8 chars) **only if** backend already provides masked/redacted values or a flag indicating safe display; UI must not invent masking policy for PII beyond “do not log” (DECISION-INVENTORY-006).
- `displayTitle`:
  - Prefer `year make model` if present; else `unitNumber`; else `licensePlate`; else `Vehicle`.

## 9. Service Contracts (Frontend Perspective)

> Moqui must proxy CRM calls server-side; browser must not call CRM snapshot directly (DECISION-INVENTORY-004). UI calls Moqui REST endpoints; Moqui invokes CRM services/endpoints.

### Load/view calls
- Optional: if `q` is provided in URL and length >= 3, auto-run search on entry.

### Create/update calls
- None.

### Submit/transition calls

1. **Vehicle search (Moqui REST)**
   - `POST /rest/api/v1/crm/vehicles/search`
   - Request JSON:
     ```json
     { "query": "ABC", "pageIndex": 0, "pageSize": 25 }
     ```
   - Response JSON:
     ```json
     { "items": [ { "vehicleId": "..." } ], "pageIndex": 0, "pageSize": 25, "total": 1 }
     ```
   - Notes:
     - Minimum query length enforced (3).
     - Pagination required (DECISION-INVENTORY-013).

2. **Vehicle snapshot (Moqui REST)**
   - `GET /rest/api/v1/crm/vehicles/{vehicleId}/snapshot`
   - Response JSON includes at least `vehicleId` and optionally owner fields.
   - Notes:
     - Server-to-server proxy to CRM snapshot (DECISION-INVENTORY-004, DECISION-INVENTORY-013).

### Error handling expectations
- Standard error payload shape (frontend expectation):
  - `errorCode` (string)
  - `message` (string)
  - optional `fieldErrors` (object map)
- `400`:
  - If `errorCode=QUERY_TOO_SHORT` or `fieldErrors.query`, show field error.
- `403`:
  - Show access denied state; do not retry automatically.
- `404` (snapshot):
  - Show snapshot error and return to results.
- `409`:
  - Show conflict message; allow retry.
- `5xx`:
  - Show banner with retry.
- Client telemetry/logging:
  - Must not include VIN/license plate values or raw query text; may include query length and selected `vehicleId` (DECISION-INVENTORY-004, DECISION-INVENTORY-006).

## 10. State Model & Transitions

### Allowed UI states
- `idle`
- `searching`
- `results`
- `empty`
- `error`
- `loadingSnapshot`
- `snapshotError`
- `completed`

### Role-based transitions
- Without permission:
  - Entering screen or calling search returns `403`; UI transitions to `accessDenied` (modeled as `error` with `FORBIDDEN`) and provides “Back”.
- With permission:
  - `idle → searching → results|empty|error`
  - `results → loadingSnapshot → completed|snapshotError`

### UI behavior per state
- `idle`: show search form; results area hidden until first search.
- `searching`: show loading indicator; disable Search.
- `results`: show list + pagination; enable Select.
- `empty`: show empty state; keep query editable.
- `loadingSnapshot`: disable all Select actions; show row-level or global loading.
- `snapshotError`: show error banner; allow returning to results and reselecting.
- `completed`: redirect to `returnUrl` with parameters.

## 11. Alternate / Error Flows

1. **Query shorter than 3**
   - UI blocks submit and shows helper text.
   - If backend returns 400, show field error and do not clear query.

2. **No matches**
   - Show “No vehicles found” and keep prior query visible.

3. **Many matches**
   - Use pagination; show total count.
   - Encourage refining query; do not claim truncation unless backend provides `total`.

4. **Unauthorized (403)**
   - Show access denied state; provide “Back” to `returnUrl` (without vehicleId).

5. **Network timeout / transient failure**
   - Show retry banner; preserve query and last results if any.

6. **Vehicle missing on snapshot (404)**
   - Show message; return to results; user may re-run search.

7. **Conflict (409)**
   - Show message; allow retry snapshot load or reselect.

## 12. Acceptance Criteria

### Scenario 1: Query length enforcement (client-side)
**Given** the Service Advisor is on the Vehicle Lookup screen  
**When** the advisor enters a query with fewer than 3 characters  
**Then** the Search action is disabled  
**And** the UI indicates the minimum length requirement is 3 characters

### Scenario 2: Search returns paginated matches with owner context when available
**Given** the Service Advisor is authenticated and authorized to search vehicles  
**And** the backend has at least one matching vehicle for query `FLEET-A5`  
**When** the advisor submits a search for `FLEET-A5` with `pageIndex=0` and `pageSize=25`  
**Then** the UI displays the returned `items`  
**And** the UI displays pagination using `pageIndex`, `pageSize`, and `total`  
**And** for any item that includes `ownerDisplayName`, the UI renders it as plain text

### Scenario 3: Optional match metadata is display-only
**Given** the advisor is authorized  
**And** the search response includes `matchType` and `rankScore` for at least one item  
**When** the UI renders results  
**Then** the UI displays `matchType`/`rankScore` if present  
**And** the UI does not compute or alter ranking client-side

### Scenario 4: No matches shows empty state
**Given** the advisor is authorized  
**When** the advisor searches for `NONEXISTENT123`  
**And** the backend returns `items=[]` and `total=0`  
**Then** the UI shows an empty state message  
**And** no results rows are displayed

### Scenario 5: Selecting a result loads snapshot and returns to caller with vehicleId
**Given** a prior search returned a result with `vehicleId = "aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa"`  
**And** the Vehicle Lookup screen was opened with `returnUrl=/pos/estimate/create`  
**When** the advisor selects that result  
**Then** the frontend calls `GET /rest/api/v1/crm/vehicles/aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa/snapshot`  
**And** on success, the browser navigates to `/pos/estimate/create?vehicleId=aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa`  
**And** if the snapshot response includes `ownerPartyId`, the browser also includes `partyId=<ownerPartyId>` in the return URL

### Scenario 6: Backend validation error maps to field error
**Given** the advisor is authorized  
**When** the advisor submits a search and the backend responds `400` with `fieldErrors.query`  
**Then** the UI displays the error message associated with the search input  
**And** the advisor can correct the query and retry

### Scenario 7: Unauthorized access is handled safely
**Given** the user is authenticated but lacks vehicle lookup permission  
**When** the user navigates to Vehicle Lookup or submits a search  
**Then** the UI shows an access denied state  
**And** no vehicle/owner data is displayed

### Scenario 8: Client telemetry does not include VIN/plate/query text
**Given** the advisor performs a search and views results containing VIN and license plate values  
**When** client-side telemetry/logging is inspected for the session  
**Then** no VIN, license plate, or raw query text values are present  
**And** telemetry may include query length, result count, and selected `vehicleId`
